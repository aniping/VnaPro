# TDC1VN08 / TDC1VN10 模拟驱动切换

当前以 **TDC1VN10 新接口**为基准，服务默认加载 VN10 模拟库。TDC1VN08 旧模拟器保留，命名为 `tdc1vn08_drv_sim`；底层接口、数据布局和噪声生成规则不受应用配置的端口数影响。

## 对应关系

| 驱动接口 | 模块目录 / 合同 | CMake target | Windows MinGW 动态库 | `driver.board` |
| --- | --- | --- | --- | --- |
| TDC1VN08 旧接口 | [VnaNativeSimulator](../VnaNativeSimulator/README.md) / [native_api_contract.h](../VnaNativeSimulator/include/vna_native/native_api_contract.h) | `tdc1vn08_drv_sim` | `libtdc1vn08_drv_sim.dll` | `tdc1vn08` |
| TDC1VN10 新接口 | [VnaBoardSimulator](../VnaBoardSimulator/README.md) / [board_api_contract.h](../VnaBoardSimulator/include/vna_board/board_api_contract.h) | `tdc1vn10_drv_sim` | `libtdc1vn10_drv_sim.dll` | `tdc1vn10` |

Linux 对应 `libtdc1vn08_drv_sim.so`、`libtdc1vn10_drv_sim.so`；macOS 对应 `libtdc1vn08_drv_sim.dylib`、`libtdc1vn10_drv_sim.dylib`。Windows MSVC 的 DLL 通常没有 MinGW 的 `lib` 前缀；CMake 生成的配置会使用实际工具链的产物名称。从仓库根目录构建时，两库及 `vna_server` 输出到构建目录的 `bin` 下，例如 CLion 的 `cmake-build-debug/bin`。构建 `vna_server` 还会自动构建前端并在项目根目录生成完整 `release` 发布包，步骤见[自动生成发布目录](../README.md#自动生成发布目录)。单独构建模拟模块只生成该模块，不生成服务或完整发布包。

两个接口有同名但不同签名的函数，必须同时匹配 **接口选择**和**动态库**。`driver.board` 表示驱动 ABI，不能只看物理板卡名称：后续 VN08 驱动若已对齐 VN10 函数签名，应选择 `tdc1vn10`，库名则填写实际提供新 ABI 的文件名。

## 配置与切换

程序固定读取可执行文件同目录的 `vnapro.yml`，不接受启动参数；CLion 的 Program arguments 留空。驱动库也从程序同目录加载，`driver.library` 只填写编译后的文件名，不能填写路径。Windows MinGW 默认 VN10 配置：

```yaml
driver:
  type: simulator
  board: tdc1vn10
  library: libtdc1vn10_drv_sim.dll
  simulator:
    mode: noise
    seed: 42
    noiseAmplitude: 0.002
```

切换到保留的 VN08 旧接口时，同时修改两项：

```yaml
driver:
  type: simulator
  board: tdc1vn08
  library: libtdc1vn08_drv_sim.dll
  simulator:
    mode: noise
    seed: 42
    noiseAmplitude: 0.002
```

1. 停止正在运行的 `vna_server`。
2. 从 CLion `vna_server` 目标运行时，编辑 `cmake-build-debug/bin/vnapro.yml`；运行发布程序时，编辑 `release/vnapro.yml`。
3. 同时修改 `driver.board` 和 `driver.library`，保留其他网络、仪器和日志配置。
4. 无参数重新启动，查看 INFO 启动日志的 `board`、`driver` 和模拟模式，确认加载的是目标接口和库。

加载真实库时将 `driver.type` 改为 `hardware`，同时填写真实库文件名及对应 ABI。省略类型也按 `hardware` 处理；已有模拟配置必须明确添加 `type: simulator`。硬件路径完全忽略 `driver.simulator`，不校验其中的模式、种子和幅度，也不设置模拟环境变量；遗留模拟参数不能妨碍真实库启动。真实库自身加载、初始化或下发失败仍报告原始调用步骤与错误码。服务允许非模拟器 IDN；VN10 没有 IDN 查询，显示通用适配器标识。VN10 已确认频率/IFBW 使用 Hz、功率原始值 0 合法、端口 0～3、返回 0 成功；原始功率通过 `instrument.sweep.defaultPowerRaw` 明确填写，不作为 dBm 解读。

VN10 的 RF OFF 只关端口，不停止扫描；运行期不卸载 DLL。正常关闭等整帧取数返回后关端口并退出主机 worker，驱动与借出数组保留到进程退出。Start/Get 返回失败不能证明扫描结束，此时不允许重新初始化，Close 会报告结束状态未知；RF OFF 本身失败也保留原码，不能伪造关闭成功。驱动原生读取永久阻塞时，现有 ABI 没有取消或超时能力，不能承诺限时退出。

仅模拟类型省略 `driver.library` 时按所选 ABI 使用对应构建库名；真实类型必须明确填写库文件名，不回退加载模拟库。明确填写时必须自行保持 ABI 与库匹配。运行期间无法热切换接口，刷新网页不会重新加载驱动。两种驱动共用同一套仪器服务、WebUI 和配置文件，无需维护两套前端控制逻辑。

## 模拟噪声

`driver.simulator.mode` 只接受 `noise` 或 `golden`；`noise` 在每次成功采集时加入复数噪声，`golden` 使用固定黄金向量。`seed` 为 0…18446744073709551615 的整数，相同种子、幅度与相同扫描过程可重放；缺少模式和种子时分别使用 `golden`、42。默认发布模板显式配置 `noise`、42，便于观察连续采集变化。

`noiseAmplitude` 为相对 IQ 波幅的无量纲系数，范围 0…1，默认 `0.002`（0.2%）保持原有噪声。`0` 不产生扰动，`0.01` 的逐分量扰动为默认幅度的 5 倍；允许不加引号的十进制数或科学计数法。它不是 dB 值，也不控制扫频耗时。VN08 的复数扰动模不超过原波幅乘该系数；VN10 沿用原模型，实轴不超过该系数乘原实部绝对值，虚轴不超过该系数乘原波幅，复数扰动模至多为原波幅乘该系数再乘 √2。增大噪声只放大扰动，不改变平滑基线或数据布局。

仅 `driver.type: simulator` 时，服务在加载驱动前将配置传给模拟接口，覆盖进程内旧的 `VNAPRO_SIM_MODE` / `VNAPRO_SIM_SEED` / `VNAPRO_SIM_NOISE_AMPLITUDE` 环境变量。CLion 直接编辑 YAML；独立调用模拟 DLL 时可以使用这三个环境变量。模式、种子和幅度在初始化时冻结，修改后需要重启服务；`golden` 忽略噪声幅度，仍返回原始黄金向量。模拟类型的 INFO 日志打印实际模式、种子和幅度，非法、非有限或下溢为零的非零幅度在加载驱动前报告配置路径并退出。

## 构建与部署

在仓库根目录执行：

```powershell
$env:PATH = 'I:/mingw64/bin;' + $env:PATH
cmake --build cmake-build-debug --target vna_server --parallel
.\release\vna_server.exe
```

以上 PATH 用于 Windows MinGW 构建及原 `bin` 开发运行；完整 `release` 包已携带编译器运行库，部署时无需工具链 PATH。复制整个发布目录即可迁移，程序从自身目录读取驱动、配置与默认 WebUI，与启动工作目录无关。自定义驱动也应先放到程序同目录，再填写实际库文件名；不能只将旧 DLL 改名后当作另一个 ABI 加载。

Linux/macOS 从发布目录无参数启动：

```bash
./release/vna_server
```

对应 YAML 中使用当前平台生成的库文件名。自动发布收集的运行库随程序携带；本次发布运行验证使用 Windows MinGW，其他工具链与平台需在对应环境复验。公司离线构建继续使用 `third-part` 中的压缩包，不增加 C++ 下载步骤。

SCPI 默认 `127.0.0.1:5025`，Web 默认 `http://127.0.0.1:8080/`；其他地址、端口和 Web 开关在 `server` 下配置，详见[网络与驱动配置](../README.md#网络与驱动配置)。已有发布 `vnapro.yml` 在重新构建时保留，最新生成配置在 `vnapro.example.yml`；增加配置块或换工具链后，对照示例合并，再重启。

## 验证入口

从仓库根目录完成全目标构建后，运行两种模拟器及对应核心集成测试：

```powershell
cmake --build cmake-build-debug --parallel
cmake -E chdir cmake-build-debug ctest -R '^(native_|board_|core_native|core_board)' --output-on-failure
```

CTest 名称保持 `native_*` 和 `board_*` 分类。启动日志打印实际配置和加载路径；成功启动后，浏览器和 SCPI 使用配置的入口验证完整采集链路。
