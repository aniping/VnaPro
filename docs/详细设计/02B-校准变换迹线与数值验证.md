## 6. L4：确定性数值核心

### 6.5 校准数值核心（`VnaCalibrationCore`）

分为纯数据和纯算法。产品校准资源及运行 Evidence envelope 由 L7/L6 拥有，L5 验证后降低为下列 L4 数值输入：

- `CalibrationNumericDefinition`：已经解析的 Connector、Kit、Standard 数值模型/S-parameter table、环境数值参数及内容摘要，不含 Repository ref。
- `PreparedCalibrationNumericEvidenceSet`：访问点、有效轴、标准角色、opaque uniqueness key、输入 NumericSchema、数值视图、实际条件摘要和 Quality，不含 Session/Run/Plan identity。
- `CalibrationSolver`：SOL/SOLT/TRL 等按方法拆实现，输出候选误差项和条件数。
- `CalibrationVerifier`：硬门禁检查 L4 可见的数值证据完整性、有限值、唯一键、求解稳定性/条件数和覆盖范围；产品来源一致性由 L7/L6/L5 在降低前检查。
- `VerificationPolicy {None, Advisory, Required}` 决定独立 Check 是否影响发布；发布状态为 `Verified`、`Unverified` 或 `Warning`。`Required` 缺失/失败不得发布，`Advisory` 失败可发布 Warning，`None` 发布 Unverified。
- L4 只输出不含 CalSet ref 的 `CalibrationNumericCandidate`；它通过全部硬门禁及其 VerificationPolicy 后，才由 L7 请求 Repository 原子发布为 `CalSet`。

Core 不显示提示框、不启动采集、不读写文件、不修改活动 Channel。

#### 6.5.1 V1 一端口 SOL 三项误差模型

V1 先把一端口 SOL 做成可独立验证的完整纵向能力，再扩展 SOLT/TRL。对每个 effective point 固定：

```text
m = b_p / a_p                         // 未校正 Observation ratio
Γ                                     // 标准件或 DUT 的真实反射
D / S / R                             // Directivity / Source Match / Reflection Tracking

             R × Γ
m = D + -----------------
           1 - S × Γ
```

生产求解统一使用规范双线性系数，不使用只适合理想 Open/Short/Load 的闭式捷径：

```text
m = (A × Γ + B) / (C × Γ + 1)
A = R - D × S
B = D
C = -S

[ Γk, 1, -mk×Γk ] × [ A, B, C ]ᵀ = mk
```

三份不同标准形成复数 `3×3` 系统。校准对象只持久保存逐点 `A/B/C`；`D=B`、`S=-C`、`R=A-B×C` 只是只读诊断属性，禁止再保存一份可漂移副本。DUT 反校正固定为：

```text
Γ = (m - B) / (A - C×m)
```

有限 `|Γ|>1` 不钳制。应用稳定度为：

```text
rhoApply = |A - C×m| / (|A| + |C×m|)
```

尺度为零、分母/输入非有限或 `rhoApply < minimumApplyRcond` 时，该点输出规范 quiet NaN 和 `CorrectionIllConditioned`，不能散落硬编码 epsilon。

#### 6.5.2 机械标准与偏置模型约定（`offset convention`）

证据/决策索引：`DEC-CAL-STD-MODEL-001`（依据 `EV-COM-CAL-STD-MODEL-001`，边界 `GAP-CAL-STD-MODEL-001`）。

机械 Open/Short/Load 不是默认 `+1/-1/0`。标准定义至少包含物理实例/序列号、Connector 接口与性别、证书/模型修订、有效频段、offset line，以及下列端接之一：

- Open 的 `C0..C3` 边缘电容多项式；
- Short 的 `L0..L3` 残余电感多项式；
- 有限正实/复阻抗 Load；
- 厂家逐件表征 `Γ(f)`，带来源格式和证书身份。

内部只接收 SI。以 Hz 为自变量用 Horner 计算 `C(f)=C0+C1f+C2f²+C3f³` 和 `L(f)=L0+L1f+L2f²+L3f³`；Importer 负责 fF/pH/GHz 等单位换算并保留来源，Core 不猜单位。相量约定冻结为 `exp(+jωt)`。端接阻抗用射影对避免理想开/短路的无穷与除零：

```text
Open:  (N,D) = (1, jωC)
Short: (N,D) = (jωL, 1)
Load:  (N,D) = (Zload, 1)
ΓT = (N - Zref×D) / (N + Zref×D)
```

`KeysightAN1287TraditionalCoaxV1` 是**证据条件解禁** profile，不是凭 profile 名即可启用的常开开关。其当前唯一允许的来源 revision 为 [`SRC-KEYSIGHT-5989-4840EN-20260329`](../架构依据/01-商用品行为证据.md#src-keysight-5989-4840en-20260329)：

| 固定项 | 必须精确匹配的值 |
| --- | --- |
| 官方资产 | [Keysight DAM PDF](https://www.keysight.com/content/dam/keysight/en/doc/gate/application-notes/5989-4840.pdf) |
| 文档身份 | literature `5989-4840EN`，68 PDF 页，`Published in USA, August 21, 2024` |
| blob | `11,071,892` bytes，SHA-256 `cb890ea940c6a1fd9c678513dd63ea91ae96b4d993929c2735299c80d1615d1e` |
| 公式与语义转录 | terminated-line 式 (10)：PDF 8；loss/alternate units：PDF 9–11，PDF 11 明确 one-way loss；traditional coaxial 上下文：PDF 54–56，式 (43)：PDF 56 |

上述官方 PDF/hash 已用于设计查证，因而可以把下述式号和 Keysight coefficient convention 记为已查证设计事实；但 DAM URL 不是内容寻址，且当前发布/CI evidence bundle 尚未携带匹配 blob、采集 manifest、精确页码双人转录结果和版权/内部缓存说明。所以“设计事实已查证”不等于“发布 profile 已解禁”，`GAP-CAL-STD-MODEL-001` 仍保持开放。当前 PDF 正文没有使用“AN 1287-11”标识，profile ID 只作为既有稳定标识符保留。

Importer 的 `ProfileEvidenceGate` 只有在可移植 bundle 中同时验证 SourceId、完整 blob size/hash、manifest、上表精确 PDF 页转录、授权/缓存边界和独立复核 receipt 后，才返回 `EnabledVerifiedSource`。任一项缺失、DAM 重新下载的字节/hash 漂移、页数/转录不一致或旧 source ID 代换，都必须 fail-closed 为 `DisabledPendingPortableEvidence`，在解析参数、分配大对象或创建 `CalibrationNumericCandidate` 前返回 `ImportProfileDisabledPendingEvidence`。任何带 disabled/mismatched profile provenance 的 candidate 都不能通过硬门或发布。

下列公式映射仅对上述精确 Keysight source revision 成立，不证明 ZNB、SNA 或任意第三方校准套件采用相同表示。PDF 8 的式 (10) 给出 terminated transmission-line 反射，PDF 9–11 给出 loss 语义/换算，PDF 54–56 推导 traditional coaxial coefficient model，PDF 56 的式 (43) 给出 `alphaL/betaL/Zc`。内部 loss 统一为 `Ω/s at 1 GHz`，profile 中来源 `GΩ/s` 精确乘 `1e9`。令 `u=sqrt(f/1 GHz)`、`Zo=offset Z0`、`d=delay`、`Loss=offset loss`：

```text
alphaL = (Loss × d / (2 × Zo)) × u
betaL  = 2πfd + alphaL
g      = alphaL + j×betaL
Zc     = Zo + (1-j) × Loss/(4πf) × u
q      = exp(-2g)
r      = (Zc - Zref) / (Zc + Zref)

Γstandard =
    [r × (1 - q - r×ΓT) + q×ΓT]
    / [1 - r × (q×r + ΓT×(1-q))]
```

profile 在 `EnabledVerifiedSource` 时，生产实现使用上述有界反射域公式，独立 oracle 使用 offset-line ABCD 级联，二者不得调用同一 helper。profile 为 disabled 时，这两条路只是 reference-only 算术一致性检查，不得进入生产 import、Calibration 硬门或 CalSet 发布。完成 Schema、频段、参数和 terminal 检查后，`delay==0` 精确返回 `ΓT`；即使 loss 非零也不制造零长度损耗。极大损耗使 `q` 下溢为零是公式的有限数学极限，NaN/Inf 不是可接受结果。

机械 evaluator 的相对条件门为：

```text
rhoTerminal = |N + Zref×D| / (|N| + |Zref×D|)
rhoLine     = |Zc + Zref| / (|Zc| + |Zref|)
rhoCascade  = |1 - r×(q×r + ΓT×(1-q))|
              / (1 + |r×(q×r + ΓT×(1-q))|)
```

三者分别比较 `minimumTerminalRcond/minimumLineRcond/minimumCascadeRcond`。规则还要求 `f>0` 且位于 Standard、Connector 和 Kit 频段交集，offset Z0/Zref 为正，delay/loss 非负，全部中间量有限。C/L 拟合系数和最终 C/L 可为负，不凭直觉拒绝；最终有限 `|Γstandard|>1` 也不钳制。V1 只在 `ProfileEvidenceGate=EnabledVerifiedSource` 时接纳 `KeysightAN1287TraditionalCoaxV1`；证据条件失败、未知 convention、波导、Sliding Load、Offset Load、自动 subclass 和没有逐点 exact frequency 的表征数据，均在无副作用前返回对应 Disabled/Unsupported/ConfigurationRejected，不偷偷插值或绕过证据状态。

#### 6.5.3 校准证据、质量与完成门（`Evidence`）

每份 SOL/Check Evidence 必须来自独立的有限一次逻辑单位，且只能在 L6 的 ProcessingCompletionFence 满足后构造：Acquisition 已 terminal，全部已入队 Frame 处理完成，Repository disposition 已知，Run 为 Completed。产品/运行身份留在 L7/L6 的外层 envelope，不直接进入 L4：

```text
CalibrationEvidenceEnvelope                 // L7/L6 owner
  role + CalibrationStandardId + PhysicalStandardInstanceId
  InstrumentSessionId + SessionGeneration + WorkingSetRevision
  InitiationRecordIdentity + AdvanceEventRecordIdentity
  TargetBatchRecordIdentity + RunRecordIdentity
  DeploymentId + DeploymentRevision + DeploymentContentHash
  EffectivePlanRevision
  ObservationFrame/SchemaId + access point
  Device/firmware/driver + analog-path/factory-conditioning fingerprint
  connector/reference-plane/Zref/wave convention
  completedLogicalUnits + processing counts + ProcessingTerminal
  numerator/denominator/calculation Quality

PreparedCalibrationNumericEvidenceSet       // L5 output, L4 input
  ordered role + opaque EvidenceUniquenessKey
  immutable standard-model numeric descriptor
  Observation NumericView + Schema + access point
  effective Axis + CalibrationConditionSignatureHash
  numerator/denominator/calculation Quality
```

L7/L6 先验证 SOL 的三份 RunId、ObservationFrame 身份和物理标准实例两两不同，Check 是不参与求解的第四份独立 Run，不能复用或改标签。L5 再验证 envelope 的 Frame/terminal/Prepared identity、实际条件签名、Schema/span/axis 和计数，生成不含产品 ID 的 Prepared set；任一外层验证失败都不调用 L4。

L4 只验证 Prepared set 的数值条件和 opaque uniqueness key，不解释 Session、Run、Deployment 或 Repository identity。默认一端口 V1 要求 `{Finite,1}`、一个成功 Observation 和全部 Quality 为净；任一 numerator、denominator 或 calculation Quality 位非零，该标准点不得进入求解。Overload、Unlocked、SourceUnsettled、ReferenceLow 不能只警告后参与系数。

类型名 `CompletedEvidence` 不是真实性证明。L7/L6/L5 必须在降级为 Prepared numeric set 前逐字段重验业务唯一性、完成事实、Schema/span、axis、Prepared/deployment、provenance、实际条件和计数；L4 CalibrationVerifier 再重验自己可见的 uniqueness、Schema、轴、Quality 和有限值。软件也不能检测连接器上实际接错了什么；只有独立 Check、重复性策略和操作流程能够降低该风险。

#### 6.5.4 求解、反校正与独立检查门禁（`Check`）

逐点 `3×3` 系统使用行列缩放后的复数 SVD 或带列主元 QR，并报告：

```text
solverRcond
transformRcond = |A - B×C|
                 / (sqrt(|A|²+|B|²) × sqrt(|C|²+1))
backwardError = ||Mx-y||∞
                / (||M||∞×||x||∞ + ||y||∞)
```

**求解 Evidence 硬门。** 外层硬门只针对参与求解的三份 SOL Evidence envelope：其必需身份、独立性、Schema/轴/覆盖、Prepared/deployment/provenance、实际条件签名和完成计数必须完整一致；通过后才形成 L4 Prepared set。L4 硬门检查三个 numeric view 的 role/uniqueness、轴、标准模型、质量与数值。
任一求解输入非有限/质量不净、秩小于 3、`solverRcond < minimumSolverRcond`、`transformRcond < minimumTransformRcond`、`backwardError > maximumBackwardError` 或系数非有限都拒绝该点。V1 只有全部目标点成功才发布 CalSet；不能用 NaN 系数拼成“部分可用校准”。
这些求解硬门在所有 VerificationPolicy 下都不可绕过。数值后端必须固定版本，并由高精度独立实现交叉验证；未经验证的手写高斯消元不得进入生产。

`Solved` 不等于 `Verified`。独立 Check 先用同一 `rhoApply` 门反校正，再比较：

```text
|ΓcorrectedCheck - ΓknownCheck| <= maximumCheckError
```

**独立 Check 策略门。** Check 不参与三项误差模型求解，它的缺失或失败如何影响发布，只由冻结的 VerificationPolicy 决定：

| VerificationPolicy | 独立 Check 合同 | 发布结果 |
| --- | --- | --- |
| `Required` | 必须有一份不参与求解的独立 Check，且身份/Schema/provenance 匹配、质量为净、反校正稳定且误差达标 | 通过才发布 `Verified`；缺失、身份错误或任一失败都阻断发布 |
| `Advisory` | 有 Check 时执行同一契约；缺失、身份错误、质量/数值失败或超差都记录精确原因 | 通过发布 `Verified`；缺失或失败仍可发布，但状态必须是 `Warning` |
| `None` | 不要求独立 Check，也不得把“未执行 Check”误报为 Evidence 结构错误 | 发布 `Unverified`，不能隐式升级为 `Verified` |

独立 Check 的闭集结果要区分“缺失”、“身份/Schema/provenance 不匹配”、“质量拒绝”、“反校正病态”、“结果非有限”和“有限但超差”，不能把它们都折叠为求解 Evidence 结构错误。`maximumBackwardError` 评价线性求解，`maximumCheckError` 评价独立 Check，不能共用。

#### 6.5.5 不可变性、容量和释放

发布的 CalSet 保存逐点 A/B/C 与数值诊断、Kit/Standard/Check 身份、`CalibrationEvidenceSummaryArtifact` 精确引用、算法/阈值版本、Axis/Schema 和参考定义；默认不长期 pin 三到四份完整 Capture Evidence，更不保留采集 FrameLease。Solve 在形成不可变数值候选和内容摘要后释放 FrameLease；[D4C §9.4.3](./04C-校准工作流.md#943-发布决定与责任转移)在发布事务中生成有界摘要并按冻结 retention policy 决定是否另行保留完整 Evidence。Apply 输出新 NetworkMatrixSchema/CorrectionState 和逐点 status，不修改输入 Frame 或 CalSet。

设 Kit 标准数 `N`、点数 `P`、本次 Evidence 数 `K=3+optionalCheck`、表征记录总数 `Q`、字符串元数据字节 `L`。`checkedCalibrationPayload()` 必须在任何分配前以 checked add/multiply 计算并分别限制：

```text
Bkit       = fixed kit headers + N×model + Q×table point + L
Bprepared  = mappings + P×point index + K×P×evaluated Γstandard
Bsolution  = evidence identities + P×A/B/C + P×diagnostic
Bapply     = frame header + P×(complex value + sample status)
```

四项分别受 `maximumKit/Prepared/Solve/ApplyPayloadBytes` 限制，exact budget 通过、少 1 byte 必须失败。10,000 点仅 A/B/C 的逻辑载荷基线为 `10,000 × 3 × sizeof(complex<double>) = 480,000 B`；这不是 RSS 承诺。端到端峰值还要计入 K 份输入 Frame、Prepared 链、worker 队列和数值后端 scratch。Continuous/重试不得让 Evidence 或 workspace 随 Sweep 数无界增长。

#### 6.5.6 独立参考算法与证据条件回归向量（`oracle`）

机械模型保留以下退化向量：零 offset 理想 Open/Short/匹配 Load；`75 Ω` Load 在 `Zref=50 Ω` 得 `0.2`；`Zo=Zref/loss=0` 时 `Γstandard=ΓT×exp(-j4πfd)`；`delay=0/loss>0` 仍精确为 `ΓT`。反射域 evaluator 与不调用其 helper 的高精度 ABCD oracle 只证明两种实现对同一数学转录的一致性；它们不是两个独立来源，不能代替 `SRC-KEYSIGHT-5989-4840EN-20260329` 的固定 blob/manifest/页码复核。

以下参数是刻意非理想的 **VnaPro 合成回归输入**，输出由 Decimal-ABCD 路径 [generate_calibration_golden.py](../reference/generate_calibration_golden.py) 生成。公式基础已按上述官方 PDF/hash/页码查证，但这些合成系数与预期输出不是该 PDF 内容，也不是任何校准套件证书值。生成脚本只是实现 oracle；没有匹配 evidence manifest、反射域实现交叉、Importer 单位测试和完整 Gate/Assertion 映射时，不得用它单独通过 Gate 或支持 CalSet 发布：

```text
Zref = Zo = 50 Ω

Open C = [-0.11e-15, 6e-27, -4.39e-36, 0.179e-45]
delay = 3.0765e-11 s, loss = 1.8e9 Ω/s

Short L = [4.645e-12, -331e-24, 10.8e-33, -0.12e-42]
delay = 3.0508e-11 s, loss = 1.8e9 Ω/s

1 GHz:
  Γopen  =  0.926184584918250 - j0.376997627319937
  Γshort = -0.924172023208884 + j0.376251276041879
10 GHz:
  Γopen  = -0.744373990342976 + j0.661613521308266
  Γshort =  0.762121085010137 - j0.642980849276044
```

实/虚分量容差为 `5e-13`。脚本只依赖 Python 标准库，且不调用反射域 helper；CI 可以执行它来发现算术漂移，但脚本 exit 0、四个向量匹配或 ABCD/反射域相等都不能单独形成 Gate/发布证据。profile ID 保持稳定；它的 enabled/disabled 仅由 `ProfileEvidenceGate` 对精确 source revision 的 fail-closed 校验结果决定，不由脚本输出或测试调用方自行切换。

SOL/反校正独立金向量固定：

```text
D=0.02+j0.01, S=0.10-j0.05, R=0.90+j0.10
A=0.8975+j0.10, B=0.02+j0.01, C=-0.10+j0.05
mLoad = 0.02+j0.01
mOpen = 1.023076923076920+j0.0653846153846154
mShort=-0.792371134020619-j0.117835051546392
Γdut=0.3-j0.2 → mDut=0.310081892629663-j0.153421292083712
Γcheck=0.4+j0.2 → mCheck=0.377894736842105+j0.241578947368421
```

任意标准输入顺序都应恢复同一 A/B/C，DUT 反校正恢复 `0.3-j0.2`，独立 Check 恢复 `0.4+j0.2`。理想 SOL 闭式解只作为另一套测试 oracle，不能进入生产路径。还必须覆盖标准重合、R=0、病态矩阵、NaN/Inf、所有 rcond/backward-error 门、Evidence 重用、budget exact/少 1 byte 和 FrameLease 最终释放。

独立 Check 再做一张 `Required/Advisory/None × 通过/缺失/身份错误/质量失败/病态/非有限/超差` 的表驱动测试：`Required` 除通过外全部阻断，`Advisory` 通过为 `Verified`、其余为 `Warning`，`None` 不要求 Check 且为 `Unverified`。每格还要断言三份 SOL 求解 Evidence 的硬门不受 policy 影响。

### 6.6 网络参数变换核心（`VnaNetworkTransformCore`）

提供端口延伸、de/embed、matching network、Z/Y/T/ABCD 转换、mixed-mode 和 renormalization 的单算子纯计算。处理链是有序、受限的 `TransformStageSpec[]`，但顺序、产品模型引用、跨算子 Schema 和整链 hash 都由 L5 编译；这些算子通常不交换，不能由 UI 名称排序或 worker 临时改序。

```text
TransformStageSpec
  StageId + kind + implementation revision/hash
  input/output access point + NumericSchema constraints
  input/output PortTopologyId + parameter kind
  input/output ReferencePlaneDescriptor
  input/output mathematical Zref basis
  immutable model numeric descriptor + content digest + orientation
  applicable AxisSpans + interpolation policy
  NumericPolicy + FailurePolicy + ResourceUpperBound
```

| Stage kind | 必需输入 | 输出和 bind 硬门禁 |
| --- | --- | --- |
| PortExtension | `AP_AFTER_USER_CORRECTION` 或已变换 NetworkMatrix；每端口 delay/loss model | 更新逐端口物理 ReferencePlane；频率覆盖、方向和单位必须明确，不改写 CalSet reference plane |
| Deembed/Embed/Matching | NetworkMatrix + 已解码 fixture/network 数值视图 | 端口数、方向、连接面、Zref、Axis span 和 content digest 完整匹配；输出记录 plane-transform chain |
| ParameterConvert | 完整的 S/Z/Y/T/ABCD 矩阵点 | 只开放已验证的端口数/参数对；所需矩阵逆的 rcond 达门，不能把缺元素补零 |
| MixedMode | 单端矩阵 + disjoint mode-pair topology | pairing 无重复/遗漏，方向/归一化 convention 冻结；输出新的 PortTopologyId/Schema |
| Renormalize | NetworkMatrix + 当前/目标数学 Zref | 每端口 Zref 有限且满足 profile；只改变数学 basis，不声称移动物理参考面 |

L5 `compile/bindEffective()` 做顺序、类型、持久模型引用、拓扑和跨 Stage Schema 的检查；它用已经由 L7/Infrastructure 解析的 immutable model descriptor，逐 Axis span 验证实际轴、reference-plane chain、Zref、模型覆盖与插值策略，再逐节点调用 L4 `prepareTransformOperator()`。L4 只检查当前算子的数值前置条件并产出 `PreparedTransformOperator`。任一 span 有洞、重叠、方向不明或输入 correction state 不符，L5 拒绝整条候选；若用户排列会把需要 NetworkMatrix 的算子放到 formatted trace 后，或把同一 plane transform 应用两次，必须给字段级诊断，不能自动重排。

矩阵运算使用统一 `TransformNumericPolicy{minimumRcond, maximumBackwardError, finitePolicy}`。S↔Z/Y/T/ABCD、cascade 和 renormalization 所需线性求解都报告 rcond/backward error；低于门限、奇异或 NaN/Inf 时按冻结策略 `FailFrame`，或把该 Axis point 的整块矩阵标为 `CalculationInvalid`。V1 不用伪逆偷偷产生答案，也不把一个坏矩阵点拆成看似有效的零散元素。输入 Quality 原样保留为 upstream quality，变换本身的数值失败另写 calculation quality；Calibration Evidence profile 固定 FailFrame。

L4 prepare 以 checked arithmetic 计算当前算子的 `pointCount × portCount² × complexSize` 输出和矩阵分解 scratch 上界，预分配索引、系数和 workspace；L5 汇总整链常驻/峰值。evaluate 不逐点分配、不查字符串/Repository，也不持久化状态。模型随频率变化时只使用 Prepared operator 已批准的插值表；运行中不得加载文件。L5 把处理链编译为无第三方 DLL、无虚拟插件发现的闭集 dispatch，超预算在 admission 前拒绝。

测试至少覆盖：identity fixture、fixture 与 inverse 级联、port-extension 正反往返、S↔Z/Y 往返、两端口 T/ABCD 级联、mixed-mode 往返和 renormalization golden vectors；同时覆盖奇异/近奇异矩阵、非有限值、Zref 非法、端口方向反转、plane chain 重复、Axis 覆盖孔洞、插值边界、Quality 分离，以及 exact/少 1 byte 资源门。交叉 oracle 必须与生产矩阵 helper 独立，并按允许的商用品/Open Source 固定版本对照。

### 6.7 迹线数值核心（`VnaTraceNumericCore`）

本 Core 只负责 `AP_CHANNEL_COMPLEX` 之后的**单个迹线数值算子**。默认产品顺序仍是 `Select → TraceMath → MemoryOp → ShiftResponse → TimeTransform/Gate → Format → Smooth → Hold`，但顺序、Trace DAG、TraceId 解析和整图资源估算全部由 L5 编译。L4 只接收已经准备好的一个算子、其输入槽和只读数值视图。

| 算子 | L4 输入 → 输出 | L4 契约 |
| --- | --- | --- |
| 选择/迹线运算（Select/TraceMath） | 测量通道复数/网络数值视图 → `TraceComplex` | 逐点或完整矩阵需求已由已准备算子冻结；不查当前迹线或“最新值” |
| MemoryOp | `TraceComplexView + ExternalNumericInputView` → `TraceComplex` | 外部视图已带轴、Schema、访问点和内容摘要；L4 不见 ResultRef，不读取或解码工件 |
| ShiftResponse | `TraceComplex` → 更新相位/延迟语义的 `TraceComplex` | 参数、单位和 ReferencePlane/显示语义明确；不得冒充 PortExtension |
| TimeTransform/Gate | 完整频域 sweep → time-domain trace，或 gate 后受证明的频域 trace | 必须过 FullSweepFence；轴均匀性、window、zero-pad、FFT convention、inverse policy 在 Prepared operator 冻结 |
| Format/Smooth | complex trace → scalar/formatted trace | format 冻结单位/representation；Smooth 的 window/edge policy 明确，不能写成 Sweep Average |
| 迹线保持（Trace Hold） | 格式化迹线 + `StageStateSnapshot` → 迹线 + `StateDelta` | V1 模式闭集为 `Off | MaxHold | MinHold`；L6 唯一排序并调用冻结的状态端口；默认由运行代次内存头保存，只有显式可恢复工作流才持久化；仅在计数/通道测量任务的提交边界提交，Stop/Abort/Failed 丢弃增量 |
| 标记（Marker） | 完成 TraceSchema + 已解析的标记槽位 → `MarkerSnapshot` | 普通/参考/差值关系和耦合组已由 L5 降为局部槽位；L4 不见 MarkerId/TraceId |
| 限值检查/纹波检查 | 格式化迹线 + 已准备的分段规则 → `LimitEvaluation` / `RippleEvaluation` | 只在 `evaluationEnabled=true` 时求值；窗口可见性不影响通过/失败；无效或缺失输入一律为 `Indeterminate` |
| 带宽检查 | 格式化迹线 + 搜索域/阈值/上下限 → `BandwidthEvaluation` | 需要完整搜索域；峰值、交点或有效点不足时为 `Indeterminate`，不得用边界点伪造通过 |

Trace Hold 只保留三条容易检查的规则：

- 模式闭集为 `Off | MaxHold | MinHold`，决定后续扫频如何合并。
- `Restart/Reset` 是针对 exact Trace/StageStateRevision 的独立控制动作，只清空对应状态 head，不是长期模式。
- ZNB v74 的页级证据（PDF 470/1169）只支持 MIN/MAX/OFF 与 Restart，因此 V1 拒绝 `ClearWrite`。未来扩展必须先补厂商证据、状态提交边界和回归向量，不能从示波器术语类推。

#### 标记、限值检查、纹波检查与带宽检查的纯数值合同

[D4A 产品模型](./04A-应用会话与事务.md#91-仪器会话instrumentsession)仍是 Trace/Marker 产品身份和归属的唯一事实源，[D2C §7.3](./02C-通道编译绑定与失效.md#73-处理阶段顺序)负责把冻结的产品定义解析为下列无产品 ID 的 L4 输入。L7 `TraceAnalysisService` 冻结当前迹线输入后调用这些纯函数；L4 不从“当前激活迹线”、窗口选择或 Marker 编号反查产品图。

```text
PreparedMarkerSpec
  MarkerSlot
  role = Normal | Reference | Delta{ReferenceMarkerSlot}
  positionPolicy = FixedX | Search{kind, searchDomain, trackingPolicy}
  samplePolicy = DiscretePoint | Interpolated{algorithmRevision}
  outputFormat + x/y unit
  optional CouplingSlot + SharedStimulusSlot

PreparedLimitTestSpec
  evaluationEnabled
  ordered segments[] {Upper | Lower | Disabled, xStart/xStop, yStart/yStop}
  pointInclusionPolicy + comparisonPolicy

PreparedRippleTestSpec
  evaluationEnabled
  ordered spans[] {xStart/xStop, maximumRipple, overlapPolicy}
  valueKind + comparisonPolicy

PreparedBandwidthTestSpec
  evaluationEnabled
  searchDomain + peakPolicy + crossingPolicy
  thresholdFromPeak + optional minimumBandwidth/maximumBandwidth

TraceAnalysisEvaluation
  MarkerSnapshot[]
  optional LimitEvaluation
  optional RippleEvaluation
  optional BandwidthEvaluation
```

差值标记必须携带已解析的 `ReferenceMarkerSlot`。缺少参考标记、引用自身、参考链成环或格式/单位不兼容，都在 L5 prepare 前拒绝；L4 不猜“Marker 1”或最近激活标记。

`MarkerCoupling` 只把同一激励位置分发给已准备的多条迹线，每条迹线仍用自己的 Schema 求值。某成员轴不覆盖该位置时，该成员输出 `MarkerSnapshot=Indeterminate{OutOfRange}`；其他成员不受影响，也不能把位置静默夹到边界。

三类迹线检查的结果闭集统一为 `Disabled | Pass | Fail | Indeterminate{reason}`：

- `evaluationEnabled=false` 产生 Disabled，不是 Pass。
- `evaluationEnabled=true` 时，即使所有窗口都把该测试设为不可见，仍完整求值。窗口级 `visible/style` 只存在于 L7 的 `TraceAnalysisDisplayBinding`，由 L8 呈现；它不进入 L4/L5、数值判定或求值哈希。
- 必需点缺失、Quality 无效、数值非有限、搜索域无有效点、带宽交点不完整或分段规则不能求值时，返回 Indeterminate 和稳定原因；不得跳过坏点后宣称整体 Pass。

这里采用的是可观察商用品行为，不推断厂商内部类：SNA Guide（PDF 67–72）证明限值线/纹波辅助线隐藏后测试仍继续，SNA Program（PDF 135）证明 Marker coupling 与 delta 行为。产品身份、精确引用与局部槽位是 VnaPro 为保证确定性建立的统一内部模型。

资源上界在准备阶段使用受检算术计算，至少覆盖标记槽位/输出、联动成员和共享激励槽位、限值线分段、纹波检查域、带宽检查搜索索引与交点暂存区，以及四类求值输出。窗口级 `visible/style` 不进入 L4/L5 资源估算；绘图资源由 L8 按 `TraceAnalysisDisplayBinding` 独立预算。`evaluationEnabled=false` 可以不预留对应求值暂存区，但仍要保留有界 `Disabled` 输出槽，使结果不靠缺席猜测。

L4 使用的参考迹线数据协议只有数值语义，不含产品和存储语义：

```text
ExternalNumericInputView
  NumericSchema + ProcessingAccessPoint
  ordered Axis + completeness
  immutable values + Quality
  contentDigest

PreparedTraceOperator
  OperatorKind + algorithmRevision
  input/output OperandSlot + NumericSchema
  completeness + statefulness + failure policy
  per-operator workspace upper bound
```

`OperandSlot` 是一份已编译处理图中的局部坐标，不是 TraceId、ResultRef 或可用于重新查询数据的 capability。L6 只在拥有相应 deployment/Input Lease 时建立借用视图；L4 不能保存视图、延长 Lease 或从 contentDigest 反查工件。

每个 operator spec 声明 input/output TraceSchema、ProcessingAccessPoint、quantity/representation/unit、Axis requirement、input completeness `{Point, Window, FullSweep}`、Quality policy、statefulness 和资源上界。L4 `prepare()` 只验证单个算子的数值前置条件：复数运算不能接 scalar-only format，TimeTransform 不能接非频率轴或有孔洞 sweep，Marker 的 X/Y 单位必须与最终 TraceSchema 匹配。跨算子的 Schema 推导、拓扑和诊断聚合由 L5 完成。

质量分成上游输入质量与本算子的计算质量。迹线运算的除零/非有限、FFT 溢出、参考数据缺点、标记搜索区间无有效样本都用闭集处置；占位值不触发第二次错误。`FailurePolicy` 只能是 `FailTrace` 或经产品配置验证的 `MarkInvalidAndContinue`。保持处理不提交部分状态；限值检查/纹波检查/带宽检查的 `Disabled/Pass/Fail/Indeterminate` 是 L4 的唯一结论，界面不得重新猜测。

L4 只用受检算术计算本算子的输出和工作区上界；热路径使用已准备的偏移量/FFT 计划，不加载文件、不格式化字符串、不为每点分配。

纯数值测试覆盖：

- 参考视图轴、数值结构或读取位置不匹配，以及复数到格式化值的类型错误；
- 非均匀/缺点扫描、FFT/逆变换和门控基准向量、平滑边界；
- 迹线保持的 Off/Max/Min 与独立 Restart，以及 `StateDelta` 在 Completed/Stop/Abort 下的提交；
- 参考/差值标记、联动成员超出轴、离散/插值查读；
- 限值检查/纹波检查/带宽检查四态真值表，以及隐藏显示但仍求值；
- 每个算子和整组输出的预算恰好满足/少 1 字节。

DAG 成环、产品断引用、标记引用/联动闭包和整图资源门属于[§7.3](./02C-通道编译绑定与失效.md#73-处理阶段顺序)，不得在 L4 再实现一遍。

### 6.8 数值验证门禁

每个 Core 至少有四类测试：小型手算/解析向量、来自获准商用仪器的对照数据、与固定开源版本的交叉结果、以及不依赖具体答案的 metamorphic/property test。测试资产必须冻结 Axis、Schema、质量、参考阻抗/平面、conditioning revision 和容差来源；只比较复数数组而不比较语义不算通过。

重点故障向量包括：零/近零分母、NaN/Inf、span 边界变化、不可比较相干组、秩亏/病态激励矩阵、CalSet 覆盖空洞、插值/外推边界、奇异 Z/Y/T 转换、mixed-mode 拓扑错误、时域所需轴不均匀、状态 delta 重放及 Abort 后未提交状态。相同输入、PreparedStage 和 StateSnapshot 必须得到 bitwise 或 profile 规定容差内的确定结果。

Observation 另做表驱动质量真值测试：Direct 对每个 numerator quality 位原样传播；Ratio 覆盖两个输入 quality 的笛卡尔组合，以及 missing numerator/denominator、零/阈值分母、输入 NaN/Inf、有限输入但运算溢出。每例断言 numerator、denominator 和 CalculationQuality 三者独立，并验证 quiet-NaN placeholder 不触发第二个伪错误。

Provider conditioning 的 L4 测试只断言逐 span `Apply/VerifyAlreadyApplied/NotRequired`、CorrectionState transition、数值和 Quality；它不检查 binding、pin 或显示状态。

其余验证按责任方分开：

- User Calibration 的 binding/compatibility/ApplyDecision 正交表归[§7.4](./02C-通道编译绑定与失效.md#74-校准绑定与显示状态)；
- 稳定 binding pin/transfer 由 [D4A Bind/Unbind 持久责任交接](./04A-应用会话与事务.md#持久操作的责任交接)验证；
- 目录 gate 由 [D4E §9.1.4](./04E-产品对象删除与后台处理.md#914-校准数据集的目录移除)验证；
- Repository 反向引用由 [D4D §9.5.4](./04D-持久化结果与恢复.md#954-反向引用发布记录与物理回收)验证；
- 显示状态由 [D4B §9.3.4](./04B-保存召回与运行切换.md#934-会话内实时当前结果)验证。

任何遗漏/重复 conditioning、把 Missing 伪造成 Disabled 或把 NotRequired 投影成 CalOff 都必须在各自 owner 边界失败。
