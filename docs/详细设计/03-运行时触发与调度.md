# 详细设计 03：运行时、触发与调度（专题导航）

## 30 秒摘要

本专题细化 L6 运行时，回答三件事：一次测量由哪些运行对象组成，启动与停止怎样得到唯一最终状态，命令、外部触发或自由运行怎样推进一个或多个通道。

## 本专题的责任边界

本专题定义运行对象、运行侧端口、完成条件、Stop/Close 与测量推进协议。资源账本的字段级事实源在 [D5B 资源账本](./05B-共享基础服务.md#112-资源账本resourceledger)，本专题只消费它的准入与守恒结果。

历史结果、工作流证据、显式可恢复状态的 WAL、存储库决策、恢复字段与全局退役只在 [D4D](./04D-持久化结果与恢复.md#955-持久交付的唯一提交与恢复协议) 定义；会话内实时当前结果只在 [D4B](./04B-保存召回与运行切换.md#934-会话内实时当前结果) 定义。

结果交付分两个互不替代的维度：`CurrentDelivery = Disabled | LatestWins` 与 `DurableDelivery = None | RetainHistory | WorkflowEvidence`。处理状态另有 `StageStateRetention = RuntimeEpochEphemeral | WorkflowDurable`，不能根据结果是否持久化推导状态策略。

L6 定义 `LiveResultPort`、`DurableResultPort`、`RuntimeEpochStatePort` 与适用的 `DurableStateContributionPort`。[D3A 运行周期内状态存储](./03A-运行对象职责与端口.md#运行周期内状态存储普通扫频平均与迹线保持)在 L6 内实现 `RuntimeEpochStatePort`；[D4B 实时当前结果](./04B-保存召回与运行切换.md#934-会话内实时当前结果)与 [D4D 持久交付](./04D-持久化结果与恢复.md#955-持久交付的唯一提交与恢复协议)的 L7 适配器只实现会话实时槽和持久结果/状态 owner。`Continuous + LatestWins + None` 不签发持久能力，不建立持久责任，存储库/WAL 调用数必须为零。
