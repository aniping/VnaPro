# 原始波采集层原型说明

## 当前交付

本原型实现《原始波采集层软件设计》v0.13 的 V1 正确性范围：

- `VnaAcquisition` 直接接收已经展开的 `VnaSweepPlan`；
- Prepare 成功后生成只读 `PreparedAcquisition`，私有映射不进入公共 API；
- 一个硬件 Sweep 组装为一份不可变 `RawSweepFrame`；
- 支持 Finite、Continuous、Stop 和硬件 Abort；
- Prepare、Start、Abort 均按硬件 `CommandId` 匹配异步终态；
- 每个成功发布的 Sweep 对应连续 `sweepIndex`，每个 Run 恰好一次完成通知；
- Hardware `FrameTracker` 是逐点覆盖权威；本层以全局 sequence 和每 layout 进度偏移守住
  `IVnaHardware` 边界，不复制 coverage bitmap 或块队列；
- 原样保存 `std::complex<double>` 波值和质量位，不计算 S 参数、比值、校准或平均。

生产目标名为 `VnaAcquisition`，公共入口是
[`modules/VnaAcquisition/include/VnaAcquisition.h`](../modules/VnaAcquisition/include/VnaAcquisition.h)。

## 对象与生命周期

创建 Engine 前，调用方必须完成 Hardware 的发现、Open 和 Connect。传入的硬件对象应处于
`Idle`，且没有其他事件订阅者。Engine 存活期间独占该硬件的 Prepare、Start 和 Abort 命令以及
唯一 `Subscription`。

`IVnaAcquisitionSink` 必须比 Engine 存活更久。三个 Sink 回调都在硬件事件线程上串行执行，调用时
不持 Engine 状态锁，因此可以按公开状态规则重入 Engine。硬件终态可能在线程调用
`prepareAsync()` 或 `start()` 返回前到达，调用方只能使用回调携带的 `CommandId` 或 RunId 关联结果。

终态在状态锁内提交后会进入回调交付门禁，直到对应 `onPrepared()` 或 `onRunCompleted()` 返回。
这段时间只有正在执行终态回调的硬件事件线程可以重入；其他线程调用 `state()`、Prepare、Start、
Stop 或 Abort 会等待。终态回调不得同步等待另一个必须调用 Engine 才能完成的线程，否则会形成
应用层环形等待。

`onSweepReady()` 是 V1 的 Sweep 级反压点。Engine 在回调返回后才决定 Stop、Abort、Run 完成或
启动下一 Sweep，不保存历史帧。调用方若需要跨回调保留帧，应持有回调参数的 `shared_ptr`，并使用
自己的有界队列限制内存。

活动 Run、pending 命令或 Sink 回调尚未返回时不得销毁 Engine；也不得在任一 Sink 回调内部销毁
Engine。正常断开顺序是：等待操作收口、销毁 Engine 并同步退订，再调用 Hardware Disconnect。

## Prepare 与容量配置

工厂要求以下两项部署预算都大于零：

- `maximumRawFramePayloadBytes`：单 Sweep 组帧期 `values + quality + layout 进度偏移` 的逻辑载荷；
- `maximumPreparedMappingPayloadBytes`：布局描述符、波描述符和共享点索引的逻辑载荷。

请求计划在调用 Hardware 前执行 checked 预检；超预算返回 `UnsupportedPlan`，不产生
`onPrepared()`。Hardware Prepare 成功后，Engine 对 `effectivePlan` 和权威 layouts 使用同一公式
复核。预算恰好等于需求时允许通过，少 1 字节时拒绝。

私有映射只持有三个扁平数组：按 `LayoutId` 排序的 layout、同 layout 全部波共享的
`pointIndices`、以及保持 Hardware 波顺序的 wave 描述符。`RawWaveSeriesView` 借用帧和准备结果
内存，其有效期不超过所属 `RawSweepFrame`。

每 Sweep 另有长度为 layout 数 `L` 的临时 `nextExpectedPointOffsets`。对于 10,000 点、4 激励、
4 波的目标形状，发布帧有效 payload 是 3,200,000 B；当前 64 位工具链的组帧预算是
`3,200,000 + 4 * sizeof(size_t) = 3,200,032 B`。

## 硬件层配套变更

- 宿主 `ExecutionReport` 字段使用准确语义名 `waveBlockPointCapacity`；C ABI 1.0 与
  `VnaCapabilities::preferredBatchPoints` 保持兼容名称。
- `VnaWaveBlock::copyWaveTo()` 一次校验块范围，并批量复制一条波的复数值和质量位。目标参数是
  C++17 的“指针 + 元素数”借用，调用方必须保证两个目标缓冲区都至少包含 `pointCount` 个元素。
- 复数值逐项从 ABI 表示转换为 `std::complex<double>`，不假设二者对象布局相同。
- 五个异步控制 API 返回 `Result<CommandId>`。只有通过固定命令环和聚合计划预算准入的命令才取得
  `CommandId` 并产生终态；同步拒绝不改变采集层状态，也不产生伪回调。
- Hardware 只向采集层共享 `shared_ptr<const PreparedSweep>`，不再为 Prepare 事件复制完整计划；
  Continuous 的后续 Sweep 重置并复用准备阶段编译的覆盖表和波缓冲池。

## 构建与测试

```bash
cmake -S . -B build/acquisition-test \
  -DCMAKE_BUILD_TYPE=Debug \
  -DVNA_BUILD_TESTS=ON
cmake --build build/acquisition-test --parallel
ctest --test-dir build/acquisition-test --output-on-failure
```

采集层测试使用手写 Fake Hardware 注入乱序 ID、稀疏布局、质量位、Prepare 失败、Stop/Abort 双终态
和协议故障；Hardware 原有 Simulator 集成测试继续验证真实插件、事件队列和缓冲池链路。
当前现代编译器 Debug 104/104、独立 UBSan 104/104，以及 LLVM 22.1.8
ASan+LeakSanitizer+UBSan 104/104 均通过；三类 sanitizer 均无报告。完整命令见
《硬件适配层原型说明》的“构建与测试”。

## 生产门禁状态

不需要等“完整程序全部开发完”才能验证资源和隔离门禁。当前代码已经关闭以下工程门禁：

- Hardware 从受信配置读取 `slotCount=2`，并在建池前以 checked 算术执行 64 MiB 波池总载荷门禁；
- requested plan、stored prepared snapshot、待处理 Prepare 和 Prepare 事件滞留分别执行聚合字节预算，
  容器已预留但未使用的 `capacity()` 也计入常驻载荷；
- Prepare 事件队列及正在执行的回调共享 32 MiB 滞留预算，慢 Sink 不能积压无界代次；
- Continuous 复用同一代准备结果、`FrameTracker` 和波池，不再按 Sweep 深拷贝 plan 或重建池；
- 波数据采用固定槽位所有权转移和批量复制 API，采集热路径不创建逐点对象。
- 采集层通过 4 个假硬件用例拒绝块重放、重叠、layout 乱序和 sequence 缺口，证明
  非当前 Hardware 实现也不能绕过层边界。

数值输入已部分收敛：Simulator 在 10–30 kHz IFBW 下不得附加固定批次节流，单激励零 dwell 的
逻辑窗口按每点 100–33.334 us 计算；300 点、`B=2` 的集成测试会完整交付 150 个块，并验证窄带
等待可快速中止。这关闭的是模拟链路局部门禁，不等于真机生产吞吐验收。

当前 MacBookPro17,1（Apple M1、16 GB）已定为 Simulator 的目标场景。Release、日志关闭、
`slotCount=2` 下独立执行 3 次 4P/10k/4 激励/4 波基准，保守包络为：

- 10 kHz：逻辑 4,000.000 ms，P50/P95 墙钟不高于 4,000.139/4,000.207 ms；
- 30 kHz：逻辑 1,333.360 ms，P50/P95 墙钟不高于 1,333.449/1,333.523 ms；
- 10 MHz 压力管线：P95 延迟不高于 72.047 ms，P95 有效载荷不低于 42.358 MiB/s；
- 完整帧 allocate+copy+freeze：P95 不高于 0.233777 ms，不低于 13,054 MiB/s。

稳定本机门禁是 10/30 kHz P95 墙钟/逻辑时间 `<= 1.01`、10 MHz P95 `>= 40 MiB/s`、
完整帧组装 P95 `>= 12,000 MiB/s`，且零 `DataLoss`。构建、时间边界、完整指标和限制见
《原始波采集层软件设计》§8.4。

本机 Simulator 的吞吐目标已关闭；仍需在真机阶段验证 CPU、RSS、首批延迟、“硬件完成到下一 Sweep”
间隙 P99 和长稳。IFBW 不能单独决定真机 Sweep/s；点数、激励数、滤波器阶数、源/LO
切换和传输都会增加时间。逻辑 payload 上限也不能等同于进程 RSS；allocator、线程栈、驱动 SDK
缓冲和调用方持有的帧必须由基准另行计量。因此当前可判定功能与资源门禁可执行，但不能据
Simulator 单元/集成测试宣称真机生产吞吐已经达标。
