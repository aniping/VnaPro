# 日志轮转测试验收

## 原因与验收边界

`LoggingIntegrationTest.py` 使用单文件 1024 字节、2 个备份、单条记录上限 512 字节的真实滚动日志，当前文件与备份合计最多 3 KiB。采集结束后，`HOLD`、`*OPC?`、`SYST:ERR?` 的正常 SCPI 日志也会进入同一窗口。旧断言在这些命令之后要求历史 `VnaCore` 记录仍然存在，可能把正确淘汰旧记录判为失败。

现在按实际阶段验收：

- 单次采集完成后，立即检查真正的 `VnaCore` **TRACE** 记录，且同一行必须包含 `channel=1`、`frame=1`、`points=51`；同时检查 `VnaService` 扫描模式记录。
- 保持 HOLD、保持控制连接打开，固定追加 8 次正常 `*IDN?` 查询，使旧采集记录确定离开滚动窗口。检查旧 Core/frame 已淘汰，当前 SCPI 接收及成功执行日志存在。
- 检查恰好 3 个非空日志文件，每个不超过 1024 字节、不出现第 3 个备份，并检查保留的每一行都有时间、等级、线程和模块前缀。
- 保留配置相对目录、中文路径、非法配置/编码/仿真模式、驱动加载失败和退出前刷盘验证；同时直接检查 `console: false` 下 stdout、stderr 均为空。

生产日志实现、文件容量、单条记录上限、启动/连接超时和既有文件快照读取策略均未改动；没有增加测试重试。
