# HTTP 帧更新性能验收

## 2026-10-17 扫时控制与箭头门槛修正

首轮把 100 ms 的发布节流同时用作慢扫启用门槛，130 点、每段回读 150 ms、全扫约 450 ms 的真实 ABI 探针也会产生短暂箭头。本轮将两者分开：Auto 扫描需本轮实际经过至少 1 秒、按实测前缀估计剩余至少 0.5 秒，才首次发布预览；手动目标至少 1 秒且剩余目标时间不少于 0.5 秒时可提前启用。已启用后仍按最小 100 ms 间隔发布，完成即清除。门槛属于 VnaPro 的选择，并非 ZNB 已公开参数；不对箭头位置做时间动画。

Sweep → Sweep Params 新增 Sweep Time。Auto 保持最快回读；取消 Auto 后可用秒或毫秒输入请求时间，并点击 Apply。输入范围为有限的 `(0,100000]` 秒，Last Sweep 单独显示当前配置最近完整扫描的实测主机时间；没有完成记录时显示 `—`。修改配置清除旧实测值，不以保留的手动请求值冒充 Auto 最短时间。

软件节拍在 VN10 的真实 Get **之前**按单调时钟等待，并按目标时间选择 1–64 点回读，使长扫可持续显示进度。Auto 沿用 64 点，未增加等待。它改变主机回读/交付节拍，不改变板卡内部 RF/ADC 驻留；低于自然采集时长的目标不能让硬件变快。VN08 未提供已验证的分段能力，手动时间被明确拒绝。ZNB 与思仪实现的证据及差异见 [扫频时间与软件节拍](research/扫频时间与软件节拍.md)。

Stop Sweep 在长 Single 等待期间也可用，与原 Single 操作分别观察完成，不覆盖原操作凭据和 Promise。已授权、同运行/通道的停止请求可唤醒人工等待；完整原生数据仍在工作线程按 64 点取回，再完成原 FIFO 停止屏障。有效的同通道配置和 Close 也能结束人工等待；旧运行、其他通道停止、非法配置不误触发。不能强制取消已进入的阻塞硬件 Get。

时间配置使用现有 HTTP `/api/v1/config` 的 `sweepTimeAuto`、`sweepTimeSeconds` 字段，完整帧和校准缓存规则不变。SCPI 示例：

```text
SENS1:SWE:TIME 5S
SENS1:SWE:TIME:AUTO?
SENS1:SWE:TIME?
SENS1:SWE:TIME:AUTO ON
```

数值设置隐式关闭 Auto；同时提交数值和显式 Auto 时，显式 Auto 优先。支持 S/MS/US/NS 单位。TIME? 在手动模式返回请求秒数；Auto 返回当前配置最近完整扫描的实测主机秒数，未知返回 0。这与 ZNB 的硬件最短时间估算不同，不能据此推算逐点测量时间。

`TIME? MIN` / `TIME? MINIMUM` 因没有可靠最短时间估算而明确报错，不能把未知值 0 当成可设置下限。需要可中途停止的 SCPI 单次测试时，先单独发送 SING，再发送 HOLD；若先提交 `SING;*OPC?` 或 `*WAI`，后续命令仍遵守显式完成屏障，不会越过它执行。

独立服务加载现有 VN10 模拟 DLL，以 4 工作源、16 条 S 参数、10 MHz–40 GHz、10 kHz IFBW、0 dBm 验证。以下时间来自 Core 完整扫描的单调时钟记录，不含 HTTP 轮询耗时：

| 点数 | Auto 实测 | 手动请求 | 手动实测 |
| --- | --- | --- | --- |
| 800 | 0.499 s | 1.5 s | 1.513 s |
| 4000 | 0.491 s | 1.5 s | 1.513 s |
| 6700 | 0.499 s | 1.5 s | 1.501 s |

三组手动扫描的 HTTP 预览均出现递增的真实前缀和未采空尾，完成后返回完整点数并移除进度旁带。100000 秒目标的 Single 经公共 HTTP Stop 在约 0.5 秒内完成停止；该值包含轮询和剩余原生数据回读，不是硬件 Get 可取消时延的保证。

## 2026-10-16 慢扫局部刷新

VN10 沿用每批最多 64 点的原生回读，每段收齐所有工作源后才发布。超过 100 ms 的扫描才产生预览，最小发布间隔也为 100 ms；这是项目节流参数，不是 ZNB 的公开阈值。不会额外等待或改变扫描顺序、读取批大小；接口必须先返回整段，因此极窄 IFBW 下可能等待数秒才获得下一批点，不能保证每 100 ms 都有更新。VN08 没有已验证的分段回读能力，继续完成整扫后刷新。

`GET /api/v1/frame` 的每通道响应可附带可选字段：

```text
sweepProgress: { completedPoints: N, frame: AcquiredFrame }
```

外层保持上一完整帧；首扫尚未完成时外层仍为 `available:false`，但可有旁带。旁带的 `frame` 保留完整频轴和所有原始下标，`current:false`，序号指向正在采集的下一帧；仅 `[0,N)` 已取得，后缀 IQ 和投影为 `null`、有效位为 `false`。普通和 `encoding=packed` 两种表示语义相同；完整帧和旁带分别遵守既有每通道及多通道总采样预算。

旁带只在健康 Running、通道/run/配置/校正频轴匹配时返回；Single 等待完成期间也允许，校准采集期间隐藏。完成、停止、故障、新配置和新运行会清理过期进度；网络读取失败和断连也撤下界面进度。局部预览的内存分配失败会停用本扫预览，不会使原本正常的硬件采集故障。

SCPI 数据、完成屏障、导出和正式 Marker 仍读取完整帧；预览响应中的所有 Marker 均不可用。界面状态显示 `SWEEP`，箭头提示包含 `N/总点数` 及 Marker 使用前次完整扫描的说明。只有轴和显示/测量/校准身份一致时才拼接前次尾迹，修改配置不会混合旧条件的数据。

## 故障与复现

连续扫描使用 4000 个原始频点、四条迹线。HTTP 仍传输每条 2001 个绘图点，共 8004 个迹线采样值，响应约 0.8 MB。

基线提交 `63deec0` 下，真实帧响应约 2.7 秒，其中首字节等待约 2.6 秒。浏览器显示帧约每三秒变化一次；即使使用 HOLD 已完成帧，慢响应仍能复现。201 点四迹线的响应约 320 毫秒。

直接调用当前 C++ API 和编码器进行拆分测量：

| 4000 点、四迹线 | 耗时或次数 |
| --- | --- |
| HttpApi 构造帧响应 | 12.37 ms |
| JsonEncoder 无休眠推进 | 36.76 ms |
| Advance(256) 调用次数 | 477 |
| 分片之间固定等待 5 ms | 至少约 2380 ms |

主因是 HTTP 未参与共享网络就绪等待，增量编码每轮之后都可能等待 SCPI 的 5 ms 超时。前端实际解码、轮询和绘图路径回放未发现秒级 CPU 耗时。
