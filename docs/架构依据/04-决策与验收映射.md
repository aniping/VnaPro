### `DEC-OBJ-001`

**阶段 / Gate 断言范围**

S1：`ARCH-CHAIN-01 / CHAIN-PRODUCT@S1`

**决策内容**

- 测量通道（`Channel`）、迹线（`Trace`）、显示窗口（`DisplayPane`）和迹线显示绑定（`TraceDisplayBinding`）分离；测量通道拥有普通扫描平均（Sweep Average）策略，迹线拥有保持（Hold）、标记（Marker）、标记联动（MarkerCoupling）、限值检查、纹波检查与带宽检查定义；
- 显示窗口只持显示引用

**证据 / 内部缺口**

`EV-COM-OBJ-001`、`EV-COM-ANALYSIS-SCOPE-001`、`GAP-OBJ-INTERNAL-001`、`GAP-ANALYSIS-INTERNAL-001`

**来源分类与不可越过的边界**

- 商用品证明 Channel/Trace/Window 的可观察职责不同，并能区分 Channel Average 与 active Trace Hold/分析；不证明 VnaPro 聚合、稳定关系身份、状态存储位置或提交边界

**最低验收**

- 创建/删除/独立提交与引用完整性测试；Channel Average 不按 Trace 复制，Trace Hold 不串到兄弟 Trace；
- 参考/差值标记、标记联动和限值检查/纹波检查/带宽检查定义的断引用、隐藏但继续判定、删除闭包与召回往返；
- 删除显示窗口不删除迹线，删除迹线不删除测量量，非法断引用失败关闭

### `DEC-OBJ-MEAS-001`

**阶段 / Gate 断言范围**

S1：`ARCH-CHAIN-01 / CHAIN-PRODUCT@S1`

**决策内容**

- 引入独立 `MeasurementId`，使测量量（`Measurement`）生命周期不由窗口或迹线控件拥有；
- 用删除、无显示和跨迹线引用契约测试验证

**证据 / 内部缺口**

`EV-COM-MEAS-001`、`GAP-OBJ-MEAS-INTERNAL-001`

**来源分类与不可越过的边界**

- 创建后再显示的行为支持独立寿命；
- 独立测量量聚合仍是兼容多种外观的项目推断

**最低验收**

无迹线的测量量、多个迹线引用同一测量量、删除/级联与召回往返

### `DEC-ACQ-PARTIAL-001`

**阶段 / Gate 断言范围**

- R1：`ARCH-TYPE-01 / TYPE-L0-L3@R1` 只冻结 Partial 身份与 schema 表达；
- S4：`ARCH-NUM-01 / NUM-MATRIX@S4` 验证多激励完整矩阵；
- S5：Trigger 四门的 `TRG-GROUP-GRANULARITY@S5` 验证 Point/Segment/Partial 进度边界

**决策内容**

- Channel Compiler 显式生成 SourceState/PartialId；
- Trace 数不等于物理 Sweep 数

**证据 / 内部缺口**

`EV-COM-PARTIAL-001`、`GAP-ACQ-PARTIAL-INTERNAL-001`

**来源分类与不可越过的边界**

手册证明多 source partial 与执行顺序，内部 SourceState/PartialId 和帧键是项目表示

**最低验收**

Alternated/Chopped 对照、2-port 全矩阵、缺/重/乱 partial 和 Trace 数不影响物理 Sweep 数测试

### `DEC-ACQ-COMPLETE-001`

**决策内容**

- L3 从 EffectiveExecutionPlan 冻结本次物理 Execution 的期望键集合，只有每个期望键恰好覆盖一次才能发布不可变 Frame；
- 缺键、重键和迟到块是完整性处置，样本坏质量是数值质量处置，二者不得互相伪装；
- L3 只闭合采集终态，不等待处理、持久化或外部 ResultLease

**证据 / 内部缺口**

`EV-OSS-ASM-001`、`EV-OSS-NANO-CAP-001`、`GAP-ACQ-COMPLETE-INTERNAL-001`

**来源分类与不可越过的边界**

固定开源代码证明完整 point/stage 后发布是可行机制，不能证明商用品使用相同 key/组帧结构

**最低验收**

- Simulator 乱序、重复、缺块、坏质量和 late block；
- 期望键恰覆盖一次才冻结 Frame，坏质量不得伪装缺块

### `DEC-DRIVER-ISOLATION-001`

**决策内容**

- 把第三方/厂商驱动视为可能崩溃、越界或永久不返回的不可信边界；
- VnaPro 用可终止 Driver Host 进程、generation fence 和有界接管围栏旧软件，不把线程取消当作强隔离；
- Driver Host 内独立于厂商阻塞 worker 的安全控制环监视主进程租约，并只按已证实设备能力尝试 disarm/stop/abort/射频安全动作；
- `SoftwareFenceEvidence` 只证明旧 ProcessEpoch/HostGeneration 不能再发命令或发布回调，绝不等于 `PhysicalQuiescenceEvidence`。后者只能来自设备状态回读、硬件看门狗/互锁或独立安全通道；无法证明时必须 `PhysicalStateUnknownQuarantined`，禁止同一物理设备 Open/Prepare/Arm/Start/复用；
- 该选择由 fault-injection 证明，不冒充商用品内部实现

**证据 / 内部缺口**

`EV-REV-DRIVER-SEAM-001`、`EV-OSS-BOUND-001`、`GAP-DRIVER-BLOCKING-INTERNAL-001`

**来源分类与不可越过的边界**

- 来源只证明设备 I/O seam 与有界等待机制可行；
- 永久阻塞威胁模型、独立 Host、generation fence 和接管协议都是 VnaPro 可靠性推断，不是 ZNB/SNA 内部实现事实

**最低验收**

- fake driver 分别在 open/read/write/close 永久阻塞、忽略 cancel、崩溃和迟到返回；
- 分别注入主进程死亡但 Host 存活、厂商 worker 阻塞、Host 同时死亡、控制 ACK 丢失和设备继续扫描；
- 主进程须在 deadline 内围栏旧 Host，新 generation 不接纳旧响应；只有独立证据满足设备后置状态才能判物理静止，否则按精确物理设备隔离，直到安全重连/复位验证或有审计人工确认；预算/句柄由唯一恢复责任方收口

### `DEC-DEPLOY-CONC-001`

**阶段 / Gate 断言范围**

R2：`ARCH-CONC-01 / CONC-RUNTIME@R2`

**决策内容**

- R2 只冻结 Prepare、Rebind、supersede、Stop/Abort/Close 与 capability 所有权的并发协议；
- 同一 `DeviceSession` 最多一个 Prepare 单飞槽，move-only capability 在 candidate、installed record 与 retirement owner 之间只能单主；
- 外部回调不得在内部锁内执行，旧 generation 的迟到成功不得覆盖新 owner。

本决策不包含 S1 的 Channel live-Initiation 策略、产品 Result provenance 或实时当前结果；后续阶段不能反向改写 R2 回执的含义。

**证据 / 内部缺口**

`GAP-DEPLOY-CONC-INTERNAL-001`

**来源分类与不可越过的边界**

Prepare/Rebind 的并发和 capability 转移是 VnaPro 为闭合本地所有权选择的内部协议，不是 ZNB/SNA 的内部实现事实，也不需要用商用品基数资料证明。

**最低验收**

同 DeviceSession 双 Prepare、Prepare/Close、Rebind/supersede、candidate→installed→retirement move-only owner、晚到 Handle、锁内回调与 generation fence 的确定性竞态/property test

### `DEC-RESULT-RESP-001`

**阶段 / Gate 断言范围**

R2：`ARCH-RESULT-01 / RESULT-COMMIT@R2`

**决策内容**

- R2 的通用 `Observation/Result` 出站边界为每个计划内 BoundaryEmitter 冻结有界容量和一个处置槽，但不预设结果一定进入 Repository。
- 每份计划内责任必须恰好得到 `Delivered/Rejected/NoCandidate/Invalidated/Transferred/Unused` 之一的稳定 disposition；Run 终态只等本次冻结的交付目标收口，不等待外部读者长期持有。
- 进程内诊断或实时当前交付只使用预留的内存缓冲和终态槽，不分配 ResultCommit identity，不写 WAL，不创建 ResultArtifact，不进入启动恢复。
- 只有交付计划明确选择“保留历史”或“工作流证据”时，才在首次持久副作用前建立完整 identity、最坏资源和唯一恢复责任；ACK/NACK、超时、崩溃、Close 和重启均不得形成双责任方或无责任方。

此范围只处理不透明的通用结果载荷和责任闭包。它不要求测量通道/测量量/迹线、完整来源、产品描述/来源链或结果存储库；这些由首个真正消费它们的后续范围激活，不能反向塞进 R2。

**证据 / 内部缺口**

`EV-COM-PIPE-001`、`EV-OSS-BOUND-001`、`GAP-RESULT-RESP-INTERNAL-001`

**来源分类与不可越过的边界**

- 来源只支持采集/处理可流水和有界清理机制可行；
- responsibility identity、预留、唯一 owner、unknown transfer 与 disposition 闭包均是 VnaPro 内部可靠性协议，不是商用品内部实现。

- 对象大小和 SHA-256 证明“分析的是哪个文件”，不证明报告已经保存；
- 可重跑命令证明“本机如何再次观察”，不等于另一环境已经拿到完整报告；
- 报告 bundle 只提高复核与发布能力，不改变十项 `EV-REV-*` 的事实类型，也不证明运行时顺序、线程安全、故障语义、领域所有权或商用品兼容性。

**关闭验收**

- 以[SNA 二进制证据清单 §3.1—3.2](../reference/sna-binary-evidence-manifest.md#31-关闭-gap-的采集清单)为唯一技术清单，十个对象都必须具有完整、未筛选的 `objdump -p` 输出和 stderr、退出码、报告字节数与 SHA-256，并绑定工具、环境、命令和对象身份；
- bundle manifest 必须按固定顺序登记十个报告、ObservationLocator、分发许可或内部缓存边界及 manifest/receipt 身份；
- 独立复核者必须只依赖该 bundle 完成对象、报告和观察定位复核并留下 receipt；少一个对象、少一份报告、只有摘要/命令文本/对象哈希，或依赖未登记的本机路径，均不得关闭 GAP；
- 关闭后只可把对应证据状态提升为“可移植复核”，不得据此扩大任何 `EV-REV-*` 的结论范围。

<a id="new-evidence-decision-template"></a>

## 新证据与决策登记模板

任何新增设计条目必须在评审中补一行：

```text
Decision ID：
需求/行为：
Evidence/GAP ID 与来源：
证据分类及其不能证明的边界：
本项目推断：
没有采用的替代方案：
可自动验证的契约测试：
需要真机或商用品对照的解禁项：
```

无法区分“来源事实”和“本项目推断”的设计不得成为公共接口。无法自动验证、又没有真机对照计划的物理语义不得标记为已完成。一个 Decision ID 若同时依赖观察事实与架构推断，必须同时列 Evidence 和 GAP；不能把“资料没有反对”写成支持证据。
