厂商、完整型号、固件版本、已安装选件和产品兼容配置（`Profile`）；
序列号可脱敏，但脱敏规则必须记录

### 顺序与结果

每条记录含 sequence、方向、UTC 时间、单调时间或偏移；

规范化 transcript 只作派生物并记录其生成工具版本

### 兼容性验收门的唯一状态与断言

本节是四个兼容性验收门（`GATE-COMPAT-*`）的验收范围、断言、逐产品兼容配置状态和交互记录映射的唯一事实源。`ProductProfileKey` 必须精确包含厂商、完整型号、固件和影响行为的选件集合；下表的 `{model}/{firmware}/{options}` 是待采集键模式，不是通配授权。每个实际产品兼容配置必须新增独立记录，一个域通过不得替另一个域解禁。

兼容性验收范围的唯一 `IssuerId` 是 `VnaPro.CompatibilityEvidenceAuthority`，四行共同使用 `CompatibilityAssertionScopeSerializationId = vnapro.scope.compat-pipe-fields.v1`。该版本按最初签发哈希的真实规则序列化：严格 UTF-8、拒绝 BOM、不做 Unicode 归一化；从下表去掉 Markdown 反引号并裁掉单元格两端空白后，按 `ScopeId | Version | AssertionId | 完整断言文本` 顺序用单字节 `|` 连接，不加终止换行。字段含 `|`、CR 或 LF 时校验失败。

[确定性校验器](../reference/verify_scope_registry.py)同时复算这 4 个候选验收范围。它用独立的 `CURRENT_COMPAT` 候选定义镜像精确钉住每行的域、验收门、断言、关联决策、版本、定义哈希、序列化标识和签发方标识，而不是只比较同一张表的内部自洽。运行 `python3 docs/reference/verify_scope_registry.py --manifest` 可查看定义完整性结果。这里的匹配只说明候选定义字节一致，不代表厂商兼容性已经通过，也不构成正式签发；当前八个精确产品行仍全部是 `BlockedPendingEvidence`。

兼容性登记表只接收无前导零的稳定语义化版本（SemVer）`MAJOR.MINOR.PATCH`。断言文字、证据义务、域/验收门/断言/决策归属或序列化语义任一变化，都必须签发更高版本和新哈希，把旧行加入下方历史表，并同步更新校验器的当前/历史测试样例；仅重算哈希、原地改义或把当前版本指回历史版本都会失败。精确评估键及显式多域组合规则只见[D5C 厂商兼容评估键](../详细设计/05C-依赖验收与竞态.md#1231-验收门评估键与回执)。

解禁必须同时满足：精确且不含占位符的 `ProductProfileKey` 已登记，transport/protocol/runtime/storage/capability revision 均冻结，证据包哈希通过，可重复回放，对应**单域**断言全部通过。`Passed`/`Failed` 行必须按 [D5C §12.3.1 验收门评估键与回执](../详细设计/05C-依赖验收与竞态.md#1231-验收门评估键与回执)的固定字段顺序内联完整 `CompatibilityGateEvaluationKey`；六个 revision 字段必须使用 `<id>@sha256:<64-hex>`，其中 `TranscriptAndTestBundleHash` 是整个规范证据包清单的 `EvidenceBundleHash`。

评估回执固定绑定 `Outcome`、`EvaluationKeyHash`、`EvidenceBundleHash` 和 `EvaluationDefinitionHash`；完整评估键已包含 `ProductProfileKey`，因此更换产品配置会同时改变 `EvaluationKeyHash`。回执还必须引用受保护 Git 提交或标签、CI 运行和人工审批记录，不能使用 `latest` 或自由文本代替。

当前没有对应精确产品配置的真机交互记录，也没有受保护兼容发布引用、CI 评估运行和正式人工审批记录，因此八个产品行仍为 `BlockedPendingEvidence`。阻断原因是证据和审批链尚未形成，不是缺少自建公钥仓、验签服务或验收 PKI；项目不引入这些设施。

Trigger、SCPI、DCL-Status 必须绑定精确运行配置；Recall 同时绑定精确运行与存储配置；不参与的维度也必须写带版本的明确值，不能省略。一个产品、固件、选件、运行/存储配置或域的 transcript 不能替另一行解禁，也不能证明厂商内部实现。只有发布清单显式列出多个完整 `CompatibilityGateEvaluationKey` 时才合取；不存在默认的 SCPI+DCL-Status 或 Trigger+Recall 联动。
