## 2. LibreVNA

### `EV-OSS-ASM-001`

**固定提交证据**

固件按 point/stage 收齐后才发布：[VNA.cpp 365-405](https://github.com/jankae/LibreVNA/blob/c4276df1e79c559f878ebc17e9f0bd3bd0a70f57/Software/VNA_embedded/Application/VNA.cpp#L365-L405)

**分类**

观察事实

**关联决策**

`DEC-ACQ-COMPLETE-001`、`DEC-RUN-ORTHO-001`

**取舍**

只借鉴固定顺序的 point/stage 计数、阶段完成后发布及 stage/source 身份；该源码不证明任意键集合、跨线程去重或 exactly-once 发布

### `EV-OSS-BOUND-001`

**固定提交证据**

USB 空间等待超时后清理并终止 Sweep：[VNA.cpp 536-549](https://github.com/jankae/LibreVNA/blob/c4276df1e79c559f878ebc17e9f0bd3bd0a70f57/Software/VNA_embedded/Application/VNA.cpp#L536-L549)

**分类**

观察事实

**关联决策**

`DEC-RES-BOUND-001`、`DEC-RUN-ORTHO-001`、`DEC-DRIVER-ISOLATION-001`、`DEC-RESULT-RESP-001`

**取舍**

- 借鉴容量 + timeout + 明确终态；
- USB 等待超时不证明进程隔离、完整资源账本或结果提交责任，仍需 VnaPro 自己的端到端 Credit、Driver Host 和故障注入验收

### `EV-OSS-TYPE-001`

**固定提交证据**

TraceMath 以 `DataType` 区分部分轴/变换数据类别，并在输出类型为 `Invalid` 时拒绝不合组合：[`tracemath.h` 64-107](https://github.com/jankae/LibreVNA/blob/c4276df1e79c559f878ebc17e9f0bd3bd0a70f57/Software/PC_Application/LibreVNA-GUI/Traces/Math/tracemath.h#L64-L107)、[`tracemath.cpp` 228-240](https://github.com/jankae/LibreVNA/blob/c4276df1e79c559f878ebc17e9f0bd3bd0a70f57/Software/PC_Application/LibreVNA-GUI/Traces/Math/tracemath.cpp#L228-L240)

**分类**

可取机制，但不证明完整物理量域

**关联决策**

`DEC-NUM-SCHEMA-001`

**取舍**

- 借鉴“阶段声明并检查输入/输出类别”；
- VnaPro 另补 Quantity/Correction/ReferencePlane/AccessPoint 与 NumericSchema 家族，不能声称 LibreVNA 已提供这些语义

### `EV-OSS-XFORM-001`

**固定提交证据**

Deembedding 按有序 options 执行：[deembedding.cpp 162-200](https://github.com/jankae/LibreVNA/blob/c4276df1e79c559f878ebc17e9f0bd3bd0a70f57/Software/PC_Application/LibreVNA-GUI/VNA/Deembedding/deembedding.cpp#L162-L200)

**分类**

可取机制

**关联决策**

`DEC-XFORM-ORDER-001`

**取舍**

- 编译为不可变受约束序列；
- 不接受无 Schema/参考平面校验的任意换序

### `EV-OSS-COUPLING-001`

**固定提交证据**

`NewDatapoint()` 同一 Qt 回调做平均、校准、Trace、去嵌和 Marker：[vna.cpp 959-1091](https://github.com/jankae/LibreVNA/blob/c4276df1e79c559f878ebc17e9f0bd3bd0a70f57/Software/PC_Application/LibreVNA-GUI/VNA/vna.cpp#L959-L1091)

**分类**

拒绝照搬

**关联决策**

`DEC-LAYER-PURECORE-001`

**取舍**

功能顺序可参考，所有权/线程/模块边界不可参考

### `EV-OSS-NAMING-001`

**固定提交证据**

Driver 内直接 `input/ref` 生成字符串 Sij：[librevnadriver.cpp 764-795](https://github.com/jankae/LibreVNA/blob/c4276df1e79c559f878ebc17e9f0bd3bd0a70f57/Software/PC_Application/LibreVNA-GUI/Device/LibreVNA/librevnadriver.cpp#L764-L795)

**分类**

拒绝照搬

**关联决策**

`DEC-NUM-NETMODEL-001`

**取舍**

- VnaPro 保留逐序列 raw WaveSchema 和 provenance；
- 未通过网络模型证明不得命名 Sij

### `EV-OSS-CAL-COUPLING-001`

**固定提交证据**

Calibration 同时继承 QObject/Savable/SCPINode 并含 workflow/solver/file/UI：[calibration.h 12-118](https://github.com/jankae/LibreVNA/blob/c4276df1e79c559f878ebc17e9f0bd3bd0a70f57/Software/PC_Application/LibreVNA-GUI/Calibration/calibration.h#L12-L118)

**分类**

拒绝照搬

**关联决策**

`DEC-CAL-OWN-001`、`DEC-LAYER-PURECORE-001`

**取舍**

拆 Solver、Workflow、Repository、Correction Stage

LibreVNA 的 SNA5000A driver 是通过成品 SCPI 控制外部仪器的 Adapter，不是 SNA 内部架构证据。

## 3. NanoVNA

### `EV-OSS-NANO-CAP-001`

**固定提交观察**

- 固定提交的 [`nanovna.h` 40-41](https://github.com/ttrftech/NanoVNA/blob/d02db797a7032822137882f8f8a6c4ec21f064cd/nanovna.h#L40-L41) 定义 `POINTS_COUNT=101` 和 `measured[2][POINTS_COUNT][2]`；
- [`main.c` 106-147](https://github.com/ttrftech/NanoVNA/blob/d02db797a7032822137882f8f8a6c4ec21f064cd/main.c#L106-L147) 仅在 `sweep()` 返回 completed 后进行时域变换、索引与完整 flush

**分类**

可取机制

**关联决策**

`DEC-RES-BOUND-001`、`DEC-ACQ-COMPLETE-001`

**取舍**

- 借鉴容量在编译/配置期确定、完整 Sweep 才刷新完整显示；
- 不照搬固定产品上限，也不把显示 flush 当作 VnaPro 的持久化发布协议

### `EV-OSS-NANO-COUPLING-001`

**固定提交观察**

- 固定提交的 [`main.c` 857-896](https://github.com/ttrftech/NanoVNA/blob/d02db797a7032822137882f8f8a6c4ec21f064cd/main.c#L857-L896) 在同一采集循环写全局 `measured` 并直接调用误差校正和电延迟；
- 具体原地修改见 [`main.c` 1294-1336](https://github.com/ttrftech/NanoVNA/blob/d02db797a7032822137882f8f8a6c4ec21f064cd/main.c#L1294-L1336)，同一 sweep thread 还处理 UI/绘制见 [`main.c` 106-147](https://github.com/ttrftech/NanoVNA/blob/d02db797a7032822137882f8f8a6c4ec21f064cd/main.c#L106-L147)

**分类**

- 资源受限 MCU 的合理取舍；
- 桌面架构反例

**关联决策**

`DEC-LAYER-PURECORE-001`

**取舍**

拒绝移植为桌面商用架构
