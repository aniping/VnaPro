# 校准接入与使用

支持理想 50 Ω 机械校准：任意一个物理端口的 OSM/OSL、任意两个物理端口的 TOSM/SOLT，以及完整 P1～P4 的四端口 TOSM。二/四端口可选实测隔离。四端口需要逐口 O/S/M 和全部六对理想匹配互易 THRU，共 18 次标准连接；启用隔离时再测六对。未参与当前连接的端口须匹配终端。当前不使用减少 THRU 次数的补边、未知 THRU 或非理想校准件模型，不能把仅 P2/P4 的双端口集当成完整四端口校准。证据见[四端口实现依据](research/四端口TOSM实现依据.md)。

先行方案位于 `reference/analysis/vnapro-calibration/implementation-plan.md`，原程序分析位于 `reference/analysis/sna`。实现保留原校准公式、系数角色和数组顺序，以及原始归一化之后、显示之前的接入位置；原 MFC 界面和驱动调用没有搬入产品。

## 分层与处理顺序

```mermaid
flowchart LR
    Core["VnaCore · 不可变原始 IQ 帧"] --> Measure["VnaMeasurement · 同帧 bᵢ/aⱼ"]
    Measure --> Cal["VnaCalibration · 复数误差校正"]
    Cal --> Display["VnaDisplay · 格式 / Marker / Autoscale"]
    Display --> Protocol["HTTP / SCPI / WebUI"]
    Service["VnaService · 校准集与采集事务"] -->|"不可变系数快照"| Measure
```

`VnaCalibration` 只拥有数学和系数，不依赖设备、服务、JSON 或界面。`VnaMeasurement::Calculate()` 接受可选校准数据，在提取原始比值之后校正；双端口联合读取同一帧四项 S 参数，保留模型耦合。原始 A/B 波不变，未覆盖的 S 参数保持未校准。逐点奇异、非有限或无效参考波返回明确错误，不以夹紧值伪装有效数据。

服务发布 `shared_ptr<const CalibrationData>`。HTTP 曲线、SCPI SDATA、Marker 和 Autoscale 使用同一数值路径，`FrameContext` 携带同一校准快照。格式及圆图解释由 `VnaDisplay` 负责，界面不计算或保存自己的误差系数。

`CalculateMany()` 在帧内复用双端口四项或四端口 16 项联合结果。四口模型按 `S=A*inverse(I+match⊙A)` 一次校正完整矩阵，A 为逐格去偏置、除跟踪后的原始矩阵，不以六次双端口校正代替。HTTP 每四条一批后立即投影，无跨帧全局缓存。

## Web 操作

1. 取得控制权，先设置频率范围、点数及 IFBW，再按右侧 **Cal**。
2. 选择 **Start (Manual)…**，在紧凑配置窗口中确认端口拓扑与 Type，再确认各端口理想 50 Ω 校准件。
3. 单端口连接 Open、Short、Match/Load；双端口需要两端各三项标准及 Thru；四端口选全四口 TOSM，需要四口各三项及全部六对 Thru。选择 Isolation 时，每个要求的端口对另接匹配负载测隔离。
4. Start 后进入校准工作区：上方为所选标准的 dB Mag / Phase 双图，下方按端口显示紧凑标准按钮。每连接一个标准，点击对应按钮。曲线只来自该标准的已确认原始测量，未采集时为空；成功状态来自服务读回。所有必需项成功后才允许 **Apply**。
5. Apply 成功后生成内存校准集并启用。使用 **Use Cal → Cal Manager…** 打开独立管理窗口选择已有集，**User Cal Active** 控制启停。默认导出 `.vcal` 二进制，另可导出 CSV；导入只接受 `.vcal` 和完整 CSV。

按右侧 **Cal**，在 Cal / Use Cal 页的 **Current Cal Set · Ch1** 查看服务端当前集名称、方法及端口；工具栏只显示仪器标识。停用或扫描条件不兼容时，校准页仍保留集名称并显示 Cal Off，长名称完整换行显示。

Cal Manager 独立窗口使用校准池表格，支持名称搜索和仅适用集筛选；只处理服务摘要，不重新读取系数文件。弹窗宽度上限 1100 px，高度按内容收缩；列表按 6 条设计，受限时保留约 5 条，搜索、表头和底部操作保持可达。常规桌面窗口采用左侧列表、右侧条件对照，详情直接显示，不设展开按钮或详情内部滚动条；完整名称、当前频段、点数、IFBW、功率、设备身份和 IFBW/插值提示均在右侧查看，列表中的长名称省略显示并保留悬停全文。宽度不超过 900 px 时上下排列。候选高亮与“通道所选”标记分别显示，仅浏览不会替换当前集；**Apply to ChN** 使用一次 `activate` 操作，准备成功后原子选择并启用，失败保留原集。条件对照区分适用性预检与系数已准备。等待受理、准备和读回使用真实操作状态，不显示虚假百分比。只读可查看和导出，导入、应用、删除要求控制权限；删除先确认名称，选择或状态变化会废弃旧确认。Esc / Close 关闭窗口并返回入口，提交期间等待操作终态。这里参考 ZNB 的通道与池分离设计，另核对思仪和 Keysight 的宽表结构，见[商用对照](research/商用网分校准集管理界面对照.md)。[ZNB 用户手册 v74 第 655 页](https://scdn.rohde-schwarz.com/ur/pws/dl_downloads/pdm/cl_manuals/user_manual/1173_9163_01/ZNB_UserManual_en_74.pdf#page=655)

校准集列表的悬停和键盘焦点均覆盖整行；点击名称或任意属性列只切换浏览候选，需按“应用并启用到 ChN”才更改通道校准。操作提交期间整行禁止切换候选，名称按钮不会重复触发行点击。

同一有效控制租约的后台续期不会临时禁用菜单或弹窗按钮，也不会插入权限提示；真实失权、断线及操作忙碌仍立即关闭相应操作。主动获取、释放控制权仍显示前台忙碌状态；释放先关闭本地写权限，并等待在途续租结束后再向服务发送释放，避免请求乱序。

Begin 时服务只保存一次进入校准前的 Trigger Source 与 Sweep Mode，再切到 MANUAL/HOLD。每次标准经过 Stop、计划准备、新 MANUAL run、Trigger、完整帧身份校验及最终 Stop，不复用旧帧或已校正曲线，也不覆盖已保存模式。Apply 或正常 Cancel 后恢复原模式：IMM/CONT 自动连续扫描，MAN 保持对应模式布防，原 HOLD 仍暂停。操作结果和 OPC 等实际核心恢复完成后才成功；恢复启动失败返回失败并保留有效新集。收集期间拒绝扫描设置及其他运行请求；取消等待已经接收的采集终结，故障后取消只清理会话并保持 HOLD，不自动重启。

原活动集在采集期间保留，只有新集完整求解成功才替换。缺少标准、奇异或无效样本不会生成成功集，失败的求解继续保留会话供重采；此时尚不恢复扫描。控制者关闭当前会话向导会取消采集并恢复原模式；观察者或旧会话的 Close 只关闭窗口，不更改服务会话。

Cal / Cal Off 是逐迹线状态：全局启用 P2/P4 集时，S22、S24、S42、S44 可校正，S21 仍为 Cal Off；原始 A/B 保留 RAW。

预览按 session、步骤、校准版本及保存的 run/frame 身份变化读取，同值状态轮询不会清空曲线或重复下载标准。收集期间仍轮询权威状态和操作结果，但暂停隐藏 DUT 完整矩阵的请求，保留原 DUT 快照；退出收集后恢复正常曲线读取。

## 兼容性与保存

校准适用性按实际整数 Hz 激励点判断，不按界面上的点数、起止频率或扫频参数是否发生变化判断。设备身份与逐点 dBm 功率仍严格匹配；功率使用有限 double，允许 −120～100 dBm，保留负数与小数。频轴必须至少包含两个严格递增的正整数 Hz 点，CW、取整后重复频点和逆序轴不支持校准。只增加源或接收机需求不改变物理刺激，不使已有集失效。

| 当前实际刺激相对于原校准集 | 处理及显示 |
| --- | --- |
| 完整原轴完全相同 | 复用原系数指针，原频点校准 |
| 每个频点均精确命中原轴，包括不连续子集 | 直接提取对应原系数，不插值；显示精确子集 |
| 全部频点在原范围内，至少一个不是原频点 | 仅新点做插值，命中点仍直接取原值；显示插值点数及持续警告 |
| 任一点超出原范围 | 整个校准停止套用，禁止外推、夹紧或只校正部分频段；提示回到原范围或重新校准 |
| IFBW 不同 | 允许使用，持续提示条件变化；减小测量 IFBW 不能消除原校准的噪声，不宣称精度不变 |
| 功率或设备身份不同 | 停止套用并提示不匹配；插值点左右两个原频点的功率都须等于该目标点功率，不对功率插值 |
| 派生系数数学校验失败 | 不使用派生结果，明确报错，不生成默认系数 |

缩小范围、改变点数甚至保持点数不变，都可能得到原点子集或新频点，必须检查实际完整频轴。插值采用 `PolarLinearV1`：复数误差项幅度线性、相位按相邻点最短弧展开后线性；任一端点幅度为零时采用实虚部直线，因为零幅相位无定义。插值始终从原集生成，避免连续改参数累积误差，派生结果通过完整数学可用性检查后发布。相邻真实相位变化超过 180°、过于稀疏的采样及未采到的尖峰无法可靠恢复；通过数学校验不等于测量精度得到保证，精度敏感时应按目标扫频重新校准。依据与适用模型差异见[一手证据](research/校准集适用性与插值证据.md)。

源校准池仍在启动时完整载入和验证，切换不延迟读盘。只为当前所选集准备目标频轴，其他集做元数据和频点预检；预检通过不表示已经执行插值数学校验。缓存以原集引用、实际 Hz 轴及功率为键，每通道按需保留当前工作轴最多 512 MiB、旧轴最多 32 MiB 派生数据；不预分配。这样同一新轴下轮流使用的多套系数不会因仅能放下六套 6700 点数据的小缓存而反复计算。仅改变 IFBW 时复用系数并刷新警告，回到保留的旧轴也可复用。

缓存不持久化，不计入原始池容量：单通道原池 1 GiB、当前轴 512 MiB、旧轴 32 MiB 是三个独立逻辑预算；整机原池仍限 1 GiB，派生预算按通道独立。提高原池上限不预分配内存，也不扩大派生预算；原轴直接共享原始系数，不占派生预算。元数据、候选临时结果和被在途快照保留的系数另有开销，这些不是进程 RSS 上限。若把大量低点数校准集增至高点数，整个目标工作集可能超过 512 MiB，此时会淘汰较旧派生项，不能保证任意规模全池永久命中。首次为某集准备新轴仍有数学计算成本，实际开销见本次验证记录，未移到逐帧读取或测量数据处理路径。

底栏独立显示当前通道的 Cal 状态，不被临时通知遮挡；断线或配置未确认时不冒称校准生效。Cal 页与管理器持续显示 IFBW、插值及不适用原因。`enabled` 表示保留的用户启用意图，`effective` 才表示当前配置下实际可用；扩频或改变功率会使 `effective=false`，恢复兼容条件可自动恢复。主动停用仍保持关闭。逐迹线覆盖及 RAW 状态独立，不因通道 Cal 生效而把未覆盖迹线标成已校准。

VN10 当前接口没有唯一设备序列号，返回的 TDC1VN10 标识只能区分接口类型，无法区分两块同型板卡。使用者必须确认校准文件来自同一实际仪器及同一连接路径；字符串匹配不能证明实机身份相同。原程序 DSP 缓冲到模型输入的完整比例/固件处理也尚需实测对照，不能把纯算法一致性当成整机接入逐位复现。

每通道最多保存 256 集、1 GiB 系数及元数据，所有通道合计最多 1 GiB；超限拒绝整个操作，删除返还预算。字节数按保存对象、名称、身份、频轴、功率和全部复数系数计算，不是进程 RSS 上限。204 套全部使用 4000 点四口数组约 610 MiB，可放入同一 Ch1 池，继续沿用 CableTest 的按名激活；无需拆通道或延迟读盘。导入只加入池，必须选择兼容集并显式启用。删除当前集会停用。导入验证版本、端口、轴及系数形状、有限数、跟踪项数值可用性；不接受原软件专有文件。

`server.calibrationStore` 默认 `calibration`，相对程序目录解析，也可使用绝对路径；空字符串关闭持久化。Ch1 完成、导入、删除和选择/激活经异步保存后才提交，HTTP operation 和 `*OPC?` 都等待这一屏障；写入失败报错并保留原池。每集默认保存为独立不可变 `.vcal` 二进制，以原子替换的 `channel-1.json` 小型 manifest（version 2）发布 ID、文件引用、完整性摘要及选择。manifest 只是事务索引，不保存系数数组。首次写系数前先发布空池基线；崩溃留下但未提交的文件在恢复时清理。重复激活复用系数文件；损坏、缺文件或摘要不符会阻止启动，不能作为空池继续运行。文件锁及 manifest 冲突检查防止多个进程静默覆盖，运行实例应使用独立存储目录。

当前服务器只持久化并启动恢复 Ch1 校准池和选择，保持校正关闭；重新设置匹配刺激后需显式激活。扫描设置、测量目录及未完成的标准采集会话不跨重启恢复；其他逻辑通道及其校准仍为进程内状态。`*RST` 保留校准池。存储文件整体备份应在服务停止后复制目录，单集交换继续使用正式 Export/Import。

删除逻辑 Ch1 不删除磁盘校准池；重启创建默认 Ch1 时仍会恢复它。要持久删除校准集，应先在 Ch1 使用校准集 Delete。保存失败保证原池与选择保留；若操作已扩展采集端口需求，采集配置版本和旧帧有效性可能已改变，应重新采集。大量导入还受 HTTP 重试正文 64 MiB、128 条操作记录及 60 秒历史预算约束；收到 `429 retry_history_full` 或 `429 operation_limit` 后等待历史过期，保持控制租约并用相同正文及 requestId 重试。

大池在监听前完整加载和校验系数，启动日志报告恢复数量及耗时。已有 `.vcal` 直接读取完整元数据、频轴、逐点功率和 binary64 系数，不读取系数 JSON、不构造数值 JSON 树，也不再生成派生缓存。格式标识为 `VNBCAL02`，小端编码，保留完整双精度及负零，一/二/四口逐点固定为 64/208/784 字节，单文件上限 8 MiB，覆盖 10001 点；头部明确记录版本、载荷长度和校验和。FNV 只检测意外损坏，不提供来源认证。完整格式见[文件格式与交换方案](research/校准集文件格式与交换方案.md)。

只支持 version 2 二进制校准池。旧 version 1 JSON 池明确拒绝启动并保留原文件，不自动迁移、不重建旧缓存，也不静默当空池。单集 JSON 导入及 JSON 系数导出接口已移除；`GET sets/{id}` 默认返回二进制文件封套。升级时应使用新的独立存储目录，旧目录应保留备份；本次未转换或修改正在运行实例的校准池。

恢复后，存储层在监听前逐值核对服务完成数学验证的冻结对象，并共享相同不可变系数指针，释放加载阶段的副本。首次 ACT 不再比较整个池。热选择只检查并复用已加载的不可变文件，更新小型 manifest 的选择字段，不解码、重建或枚举系数缓存。JSON 数字转换及旧派生缓存的历史测量保留在[VNB 模拟联调](VNB模拟联调.md)，不能当成现行二进制格式的启动成绩。

入池的三条路径（导入、恢复、标准求解完成）均完整验证并冻结系数；求解返回成功但实际校正会溢出的系数也拒绝发布。激活复查元数据、数组形状及当前仪器约束，按实际 Hz 轴分类并核对设备和功率；IFBW 不同形成警告，不单独拒绝。原轴不重复逐点执行校正矩阵验证，新生成的派生系数仍须完整数学验证。205 集池中纯服务热 ACT 的同机均值：800/4000/6700 点分别从 5.54/26.26/43.87 毫秒降到 0.36/0.17/0.18 毫秒；高点数池为 204 套 800 点加一套目标点数，不能解释为 205 套全高点数。这里不含 TCP、真实保存及采集，原始测量的 16S 校正仍需计算。

### 高点数容量与派生插值

按四口每点 96 个 double 系数、频轴及功率约 784 字节计算，205 套全 4000 点约 613 MiB，在当前每通道 1 GiB 内；全 6700 点约 1027 MiB，仍超过单通道及整机预算。按现有元数据规模，单通道最多容纳计数上限 256 套 4000 点，或 204 套 6700 点（约 1022 MiB）；108 套 880 点 SI 加 96 套 6700 点 TDR 约 552 MiB，也可放入原池。原池完整驻留不等于全部派生工作集都能缓存；改变频轴时仍独立执行当前轴 512 MiB 淘汰规则。文件大小、逻辑池预算与进程内存不同；恢复时临时存在解码和深冻结两份数据，监听前共享冻结对象并释放加载副本，仍不能把逻辑预算当作 RSS 上限。

本轮保留启动预加载，首次激活不另读系数文件。旧 JSON 4000/6700 点同机单集读取解析曾约 191/319 毫秒，这笔历史成本不能被隐藏到 ACT。未来若需要超过现预算，应分别定义持久化库存、驻留工作集和派生插值缓存的容量及淘汰规则，不能仅延迟读取就绕过当前逻辑容量限制。

现已支持前述精确子集与范围内 PolarLinearV1 插值：在配置或激活事务提交前按目标完整 Hz 轴准备共享误差项，同帧全部 16 项复用；缓存以不可变源集引用、完整目标轴及功率区分，算法固定为 PolarLinearV1，设备及 IFBW 警告独立核对。只缓存派生结果，不覆盖原校准数据，也不外推。相位跨界、零幅、非单位系数和失败回滚已有独立合成用例，首次生成、缓存命中及整轮切换开销见验证记录；真实硬件的插值精度仍需实测验收。CableTest 将 800 个原始点重采样到 4000 个分析点，与仪器实际改成 4000 个扫频点是不同需求，不能据分析点数直接推定校准集必须增大。

`.vcal` 和 CSV 保存相同的完整信息。四口按 S11、S12、…、S44 逐格存 offset/match/tracking 的实部/虚部，每频点 96 个实数，即 48 个复数存储槽；无隔离时 12 个非对角 offset 固定为零，实际拟合 36 个复数误差项。双端口按所选物理口的接收行、激励列保存，顺序为 `Df,Sf,Rf,Xr,Lr,Fr,Xf,Lf,Ff,Dr,Sr,Rr`，单端口为 `D,S,R`；每个复数均为实部再虚部。

服务导入时生成新 ID，不沿用文件来源 ID，也不自动选择或启用。文件经结构、数学、资源预算检查和深冻结后才入池。二进制上限 8 MiB，CSV 上限 32 MiB；校准 HTTP 封套及规范化重试指纹上限为 36 MiB（含 CSV 引号及换行转义余量），普通控制请求仍为 16 KiB。文件传输使用既有 JSON 协议的封套：二进制 content 为 Base64，CSV content 为 UTF-8 字符串，下载文件本身为二进制或 CSV。HTTP 协议使用 JSON 不等于支持 JSON 校准文件。

CSV 包含格式版本、来源 ID、名称、设备身份、方法/物理端口、隔离标记、IFBW 和点数；数据列为 `frequency_hz,power_dbm` 及各 Sij 的误差系数实虚部。对角为 directivity/source_match/reflection_tracking，非对角为 isolation/load_match/transmission_tracking，按接收口行、激励口列排列。十进制采用 17 位有效数字和点号；元数据文本固定带 `text:` 前缀，避免表格软件作为公式执行或将长 ID 转成浮点数。完整 CSV 可再次导入，缺列、乱序列、缺元数据、非有限数或多余数据均拒绝。表格软件编辑可能改变数值精度，原样 `.vcal` 更适合无损备份。当前不支持 Snau 文件；以后确有需求再提供独立转 CSV 工具。

所有 HTTP 会话保留的精确请求重试指纹合计最多 64 MiB，满额时新写入返回 429；已有请求仍可幂等读取。操作完成 60 秒后释放指纹正文、保留请求 ID 的过期记录并返回 410，控制者持续续租也能回收预算。导入在受理入队时冻结内容，不允许外部可写别名改动已受理系数。

## HTTP 与 SCPI

观察者可读取 `GET /api/v1/calibration`、`GET /api/v1/calibration/sets/{id}`（默认二进制封套），指定 `?format=binary` 或 `?format=csv` 返回文件封套，可与 `channelId` 同用。封套字段为 format、encoding、filename、byteLength、content。租约控制者通过 `POST /api/v1/calibration` 执行动作，使用既有 operation 查询和 requestId 重试机制：

`GET /api/v1/calibration/preview?sessionId={id}&stepId={step}` 只读返回该会话已保存标准的原始复数值、dB/Phase 投影、冻结频轴/IFBW及 runId/frameSeq；对完整序列做后端投影并返回全部原始频点（最多 10001 点），dB 与 Phase 共用连续原始采样索引，不均匀抽点。未采集、未知标准或旧会话返回 available=false，无占位曲线。预览不会修改 DUT 目录、显示状态、系数或采集核心。

| action | 额外字段 |
| --- | --- |
| begin | method=`onePort`/`twoPort`/`fourPort`, port1, port2（单端口为 0，四口固定 1/4）, includeIsolation |
| capture | sessionId, stepId（服务返回的步骤 ID） |
| finish | sessionId, name（可选） |
| cancel | sessionId |
| enable | enabled |
| select / activate / delete | setId；select 仅选择，activate 原子准备、选择并启用 |
| importFile | format=`binary`/`csv`, encoding=`base64`/`utf8`, content（编码须与格式匹配） |

请求须带 requestId 和 expectedRevision；这里是独立**校准版本**，不是扫描/显示版本。ID/版本均为十进制字符串，空闲 sessionId/selectedSetId 为 `"0"`。重试返回原操作，新请求的过期版本拒绝。Cancel 是同会话屏障，允许不大于当前版本的旧版本，以取消已排队采集；不得取消其他会话。帧返回 calibrationRevision，前端据此拒绝过期投影。

`GET /api/v1/calibration` 与 status 内的 calibration 增加 `effective` 和 `applicability`；后者包含 applicable/prepared、frequencyMode（none/exact/subset/interpolated）、reasonCode/reason、源/目标/精确/插值点数、当前频段/IFBW/功率及 warnings（ifbwChanged/interpolation）。池摘要另含设备身份、原功率上下限及自身 applicability。错误原因覆盖未选择、配置未就绪、设备、频轴、越界、功率与系数无效；客户端应展示原因而非仅凭 selectedSetId 或 enabled 判断生效。

校准 SCPI 是项目新增子集，界面参考 ZNB 并不表示完整罗德协议兼容。支持短名和对应完整头名（含 COLLECT/COLLECTION）：

```text
SENS1:CORR:COLL:METH:DEF OSM,1
SENS1:CORR:COLL:ACQ OPEN,1;*OPC?
SENS1:CORR:COLL:ACQ SHORT,1;*OPC?
SENS1:CORR:COLL:ACQ MATCH,1;*OPC?
SENS1:CORR:COLL:SAVE 'Port 1';*OPC?
SENS1:CORR?
CALC1:DATA? SDATA
CALC1:DATA? RDATA
SENS1:CORR OFF
```

每次 ACQ 前必须实际换接标准；`*OPC?` 只表示操作终结，还需检查 `SYST:ERR?`。双端口使用 `METH TOSM,2,4,ON`（最后一项默认 OFF），Thru/Isolation 使用 `ACQ THRU,2,4` / `ACQ ISOLATION,2,4`。`COLL:STAT?` 返回 IDLE/READY/BUSY，`COLL:ABOR` 取消。`CSET:CAT?` 返回真实 ID/名称对，`CSET:ACT?` 保留当前选中集的带引号 ID 读回（未选中为 `"0"`），客户端可用目录映射原始名称；`CSET:DEL` 按 ID 删除。

四端口项目语法为 `SENS1:CORR:COLL:METH TOSM,1,2,3,4[,ON]`，端口顺序必须为 1、2、3、4，四口能力不足时拒绝。逐口执行 `ACQ OPEN,p`、`ACQ SHORT,p`、`ACQ MATCH,p`，再对 `(1,2)/(1,3)/(1,4)/(2,3)/(2,4)/(3,4)` 执行 `ACQ THRU,p,q`；开启隔离时还须逐对 `ACQ ISOLATION,p,q`，最后 `COLL:SAVE 'name';*OPC?`。缺任何标准、求解失败或坏帧均不生成成功集；每次 ACQ 都触发新完整扫描。此扩展不宣称思仪或罗德完整远程校准协议兼容。

`SENS1:CORR:CSET:ACT '实际校准集名称',0;*OPC?` 按名称原样匹配并原子准备、选择和启用已有真实系数；数字、反斜杠、逗号和分号均只作为名称内容，大小写敏感。名称中的引号使用重复引号转义。单参数 ID 形式继续可用。保持当前扫频参数，完整原轴直接复用、子集直接取值，范围内新点按上述规则插值。名称不存在或重名、设备/功率不匹配、越界或派生系数无效时通过错误队列拒绝，保留原选择与扫频参数，不生成默认系数。IFBW 不同允许激活并通过状态接口持续警告。第二参数目前只支持 `0`，请求其他模式明确报错。`*OPC?` 后仍需检查 `SYST:ERR?` 和 `CORR?`；`ACT?` 表示选择，`CORR?` 表示当前实际可用的校正状态。

`RDATA` 返回未校正的所选复数测量；`SDATA` 在活动集适用且覆盖测量时返回校正值，否则返回未校准值。原始接收波两者一致。任一点无效时 SCPI 拒绝整条数组，HTTP 保留逐点有效性。

自动化严格读取使用 `CALC1:DATA:MSD? '1,2,...,16'`：序号按目标通道测量定义顺序，响应为 trace-major，每点实部/虚部。它要求活动校准兼容且覆盖全部请求项；缺失、关闭、不兼容或仅单/双端口部分覆盖时返回 `-230`，不退回 RDATA。`FORM REAL,64;:FORM:BORD SWAP` 使用小端 IEEE 定长块及单个 LF，`FORM ASCII` 恢复文本；最大 10001 点完整四口 payload 为 2,560,256 字节。

## 验证与边界

四口初版的 91 项后端/546 项前端验证及独立模拟服务诊断入口见[VNB 模拟联调](VNB模拟联调.md)。最新二进制/CSV 提交前审查另通过 12 项相关 CTest、556 项前端测试及类型检查，隔离前端构建保留；该文末记录完整启动、首次及整池切换的配对结果，不能将相关测试数当作全部 CTest 通过。

本机验收包位于 `release/calibration-validation-20261016/`，含独立新版程序和 800、4000、6700 点池，不覆盖 release 根程序或配置；启动命令、端口和数据用途见包内 `README.zh-CN.md`。原样导出再导入会保留名称并分配新 ID，产生同名集时应按新 ID 或在界面选择，名称 ACT 的歧义拒绝属于正常保护。

`calibration_math` 使用 20 组原机器码固定黄金向量及异常合同；`calibration_processing` 验证处理位置、反序/非连续端口及 RAW/覆盖边界；`service_calibration` 验证独立标准、新扫描身份、队列/取消、兼容性、池容量及失败保旧集。`calibration_protocol` / `calibration_integration` 联合验证 HTTP/SCPI、RDATA/SDATA、所有权/CAS及 201/10001 点文件往返。

真实浏览器验证了向导、采集读回、Apply、Use Cal 和端口覆盖。默认模拟器没有换接标准的物理模型：固定 golden 数据可能奇异，noise 变化也可能完成求解，两者都不能评估校准精度。没有通过界面自动替换信号来制造标准。

当前没有真实硬件标准/DUT 数据，不能承诺硬件精度或逐位一致。相对奇异阈值为 `1e-12`，错误返回替代原程序的极大值/夹紧及逆矩阵失败后继续输出策略。四口实现已用原数值核、原程序完整 18 标准机械校准链的非单位系数黄金向量，以及独立合成标准/DUT 验证，依据见[实现证据](research/四端口TOSM实现依据.md)。这些证据覆盖软件求解和校正合同，不代表完整复刻原程序应用流程。尚未接入 ECal 设备、TRL、非理想机械件频率模型及原厂文件格式；跨轴插值已支持上述保守范围及显式精度提示。
