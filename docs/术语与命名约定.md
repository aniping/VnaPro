# VnaPro 术语与命名约定

> [返回文档入口](./README.md)

本页只解决一个问题：**同一个概念始终用同一个名字，并把商用网分产品术语与内部实现标识符分开。** 产品和架构文档以中文主名称为准；英文只在首次出现或必须对应协议、类型时括注。

## 1. 商用网分产品术语

| 中文主名称 | 英文或常见界面名 | 在 VnaPro 中的含义 |
| --- | --- | --- |
| 测量通道 | Channel | 一组共同执行的激励、扫描、触发、平均和校准设置 |
| 测量量（例如 S11、S21） | Measurement / Parameter | 通道中要计算或显示的网络参数；内部标识符仍使用 `MeasurementId`，用户界面不简称“参数” |
| 迹线 | Trace | 一条有明确数值来源、处理链、格式和状态的序列；可以来自实时测量、已存结果或其他迹线，不等同于屏幕上的折线 |
| 显示窗口 | DisplayPane；ZNB Diagram / SNA Window | VnaPro 放置一条或多条迹线的显示容器；关闭窗口不等于停止测量，厂商编号和选择规则由各自厂商兼容配置（Profile）映射 |
| 限值检查 / 限值线 | Limit Test / Limit Line | “限值检查”是对迹线结果执行通过/失败判定；“限值线”是该判定边界的可视化。隐藏限值线不等于停用限值检查；内部标识符保留 `LimitTestDefinition` / `LimitLine` |
| 激励 | Stimulus | 频率、功率等施加到被测件的信号条件 |
| 扫描 | Sweep | 设备沿一次冻结的刺激轴完成的完整逻辑测量周期；单个频点或单个分段只是扫描的一部分 |
| 分段扫描 | Segmented Sweep | 各频段可以有不同点数、功率、中频带宽或延时的扫描 |
| 中频带宽 | IF bandwidth / IFBW | 接收机测量带宽；会影响速度、噪声和部分校准适用性 |
| 校准 | Calibration | 用已知标准建立系统误差模型 |
| 校正 | Correction | 把已发布的校准模型应用到测量数据 |
| 校准数据集 | CalSet | 可发布、引用并具有不可变版本的校准结果；简称“校准集”，其中一个不可变修订称“校准数据集版本” |
| 数据访问点 | Data access point | 数值处理链中的明确阶段，例如原始、校正后或格式化前；不是文件位置 |
| 可编程仪器标准命令 | SCPI | 仪器远程控制命令标准；它是入口协议，不是独立业务流程 |
| 外部数字触发输入 | External TTL | 外部触发连接器收到的 TTL 电平数字信号；它是入口来源，不等于一种新的测量推进方式 |
| 通用接口总线组执行触发 | GET | 通过通用接口总线（GPIB）发出的组执行触发消息；这里的 GET 不是网络请求方法 |

不同厂商会把测量量（`Measurement`）、迹线（`Trace`）、图表区或窗口（`Diagram/Window`）组织成不同界面。VnaPro 使用独立的测量量、迹线和显示窗口作为内部产品模型，这是本项目为一致性和多视图复用作出的选择，不宣称是 ZNB 或 SNA 的内部对象结构。

## 2. 架构文档使用的名称

| 架构正文名称 | 白话解释 | 详设中的典型标识符 |
| --- | --- | --- |
| 当前设置工作区 | 用户此刻看到并继续编辑的完整仪器设置 | `SessionWorkingSet` |
| 当前设置修订 | 一次有效修改形成的不可变设置版本 | `WorkingSetRevision` |
| 设备实际执行计划 | 设备量化、约束后真正接受的频率、功率、点数和时序 | `EffectiveExecutionPlan` |
| 已生效的可执行配置 | 设备实际执行计划与相匹配的处理计划已经完整组合，可供运行使用 | `InstalledDeploymentRecord` |
| 本次测量配置快照 | 启动时冻结的设置修订、可执行配置、校准引用和结果策略 | 冻结运行上下文 |
| 运行周期 | 一组共享同一份在内存中的运行身份和累计状态的执行世代；进程重启、会话换代或明确重配置会切换世代。它可以跨越运行保持与继续，但旧世代的信号和结果不能进入新世代 | `RuntimeEpoch` |
| 运行保持 | 停止接纳新的测量推进，处理完已接纳工作并结束旧测量运行任务；以后继续时创建新任务 | `Hold` |
| 迹线最大/最小保持 | 对指定迹线的数值按点累计最大值或最小值；它是迹线数值处理状态，不停止接纳测量推进 | `Trace Hold` / `Max Hold` / `Min Hold` |
| 线性化点 | 并发操作在逻辑上唯一“正式生效”的瞬间；用它判断边沿、停止或回执谁先发生，而不是比较线程回调先后 | linearization point |
| 测量推进方式 | 下一个逻辑测量单位由何种条件启动：命令触发、外部边沿、外部电平门或自由运行 | `MeasurementAdvanceKind` |
| 进入触发就绪状态 | 设备已为本次执行做好接收外部边沿或电平的准备；它必须由驱动或硬件给出可验证证明，不是界面上的“Ready”文字。详设精确状态也称“布防” | `LiveArmed` / `HardwareArmedReceipt` |
| 单台仪器通道序列 | 同一个设备会话按仪器已验证的通道/测量序列依次执行；由该仪器一次进入触发就绪并按自身序列推进 | `SingleInstrumentSequence` |
| 多设备同步组 | 多个设备会话需要在明确的时间误差内同步启动；除共享物理触发条件外，还必须证明参考时钟或时钟映射、触发偏斜、设备延迟/抖动和产品允许误差。只有这类拓扑才需要每台设备进入屏蔽就绪并使用硬件组激活 | `MultiDeviceSynchronizedGroup` |
| 屏蔽就绪 | 多设备同步组中的设备已经配置完成，但硬件仍保证它不能开始扫描；全部成员达到该状态后才能统一激活 | `MaskedReady` |
| 硬件组激活 | 通过共享硬件开关、触发分配器或受控触发源，一次性让多设备同步组生效；软件循环逐台开关不算 | `AtomicExternalTriggerGroupActivation` |
| 测量推进候选 | 已捕获或排队、但尚未通过全部父任务与通道准入检查的命令/外部证据/自由运行条件；可以被拒绝或取消 | `MeasurementAdvanceCandidate` |
| 已接纳的测量推进事件 | 命令、外部触发或自由运行条件已经通过能力、运行周期和路由检查；它不等于物理触发信号 | `AdvanceEvent` |
| 目标批次 | 一次已接纳的测量推进事件所冻结的完整目标通道集合 | `TargetBatch` |
| 测量运行任务 | 一次 Single、Group 或 Continuous 运行的父任务；负责运行模式、接纳开关、进度与最终状态，不等同于单次设备采集 | `Initiation` / `InitiationId` |
| 通道测量任务 | 目标批次中一个通道通过触发条件、配置、能力和容量检查后形成的逻辑任务；一次任务可以包含多次设备采集 | `VnaRunEngine` / `Run` |
| 准入检查 | 创建工作前检查设置、设备能力、资源容量和后续清理条件；检查通过本身还不代表系统已经承担该工作 | Admission |
| 已接纳 | 准入通过并在一个明确边界登记责任；从此即使调用者断开，系统也必须给这项工作一个结论 | Accepted |
| 资源额度 | 为一项已接纳或待接纳工作预留的有上限容量 | Credit |
| 最终执行状态 | 已接纳操作最终成功、停止或失败，之后不可改写 | `BusinessTerminal` |
| 恢复责任移交 | 未决外部操作已写入持久记录，并由唯一恢复责任方继续确认 | `TransferredToRecovery` |
| 删除影响对象清单 | 删除前从同一产品对象关系修订计算出的对象、引用关系和结果所属键；执行只能处理这份已确认清单 | `canonicalAffectedObjects` / `AffectedSetDigest` |
| 删除后台处理状态 | 原删除凭证已结束但后台仍在确认时，可用完整恢复身份查询的 Active、Resolved 或 Expired 只读结果；这里不是“还原已删对象” | `QueryDeleteRecoveryStatus` |
| 物理执行事实 | 分开记录设备是否已启动（已启动 / 未启动 / 未知）与当前物理处置（仍活动 / 有独立证据证明已静止 / 状态不可知且设备禁用）。软件已围栏只证明旧进程不能发命令或发布回调，不能推导设备已静止或从未启动 | `PhysicalStartKnowledge + PhysicalDisposition` |
| 实时当前结果更新 | 决定某份结果能否成为指定所属对象、读取位置和兼容条件的当前值 | `LiveCurrentSlot` / `LiveResultRef` |
| 结果协调器 | 接收数值处理产生的不可变结果候选，调用本次计划启用的实时/持久交付边界，再把稳定处置交给运行控制汇总；它属于运行控制职责 | `L6 ResultCoordinator` |

架构正文不单独使用“平面、槽、`owner`（唯一责任方）、`terminal`（最终执行状态）、`admission`（准入检查）、`handoff`（责任移交）、`projection`（只读状态视图）”等内部简称。需要表达时，优先写“四类运行职责、实时当前结果、唯一责任方、最终执行状态、准入检查、责任移交”。

四类运行职责的正式名称固定为：“配置与当前结果”、“运行控制与触发调度”、“采集与数值处理”、“资源、状态与诊断”。不再使用“产品平面、控制平面、数据平面、横切平面”作为同义词。

准入、接纳和资源额度不能混用：准入是**检查与决定**，接纳是**系统开始承担责任的事实**，资源额度是**已经预留的容量**。容量检查只是准入的一部分。

“保持”必须带上完整前缀：**运行保持（`Hold`）**是运行控制动作，**迹线最大/最小保持（`Trace Hold` / `Max Hold` / `Min Hold`）**是迹线数值处理状态。禁止用无前缀的“Hold 状态”同时表示两者。

厂商兼容入口可以按“当前选中迹线（active trace）”操作 Max/Min Hold；VnaPro 进入产品用例后必须先解析为精确迹线，不得把“当前选中”变成全局共享的数值状态。

## 3. 详细设计中的协议术语

详细设计可以保留精确标识符，但标题和解释先写中文：

首次遇到下列英文时，先按中文理解：唯一责任方（`owner`）回答“现在谁必须把工作做完”；稳定证明（`receipt`）回答“哪个事实可以重复校验”；围栏或屏障（`fence`）则是一条先后边界，必须再看具体类型才知道它是阻止新工作，还是等待旧工作处理完。

| 内部术语 | 统一中文解释 |
| --- | --- |
| owner | 唯一责任方或唯一持有者 |
| receipt | 可验证的稳定事实证明；是否写入持久存储，由所属协议明确声明，不能仅凭名称推断 |
| admission | 准入检查与决定；检查通过不等于已接纳，还要在明确边界登记责任 |
| fence | 围栏或屏障；用一条可验证的先后边界阻止新工作，或证明旧工作已处理完 |
| CompletionFence | 完成屏障；证明屏障之前已经接纳的工作都得到明确处置 |
| AdmissionFence / MutationFence | 准入围栏 / 修改围栏；阻止围栏之后产生新的工作或受保护修改，不证明旧工作已经处置完 |
| RetirementFence | 退役屏障；证明旧身份、旧运行周期或旧资源已经不能再被合法使用 |
| ProductMutationFence | 产品对象关系写围栏；删除执行期间只阻止会改变本次影响对象清单的产品修改，不阻塞无关通道 |
| lineage | 引用合法性来源链 |
| source-zero / target-one transfer | 责任原子移交：在同一个不可拆分的提交点，原责任方不再持有责任，新责任方成为唯一责任方；不存在两边都负责或两边都不负责的窗口。仅在精确恢复协议中保留英文简称 |
| projection | 只读状态视图；实时当前结果的精确协议使用 `LiveCurrentSlot` / `publish`，不再叫“先保存再投影” |
| quarantine | 对无法安全继续的精确对象进行隔离，并交给恢复流程 |
| retirement | 对外可见身份的安全退役 |
| compact | 在不改变对外语义的前提下压缩内部记录 |
| Repository | 存储库；不再译作“资源库” |

这些词只用于描述精确并发、崩溃恢复和资源协议。产品或架构读者不需要先理解它们。

## 4. 五组容易混淆的概念

### 4.1 未绑定校准集不等于用户关闭校正

- **未绑定校准集（`Unbound`，界面显示 Cal Off）**：通道没有选择校准集；S1 使用这一状态。
- **用户关闭校正（`Bound{DisabledByUser}`）**：已有合法校准绑定，但用户暂时关闭应用。
- **校准引用缺失（`MissingUnresolved`）**：原绑定无法解析，是异常状态，不能伪装成用户关闭。

### 4.2 完整采样帧不等于原始数据访问点

完整采样帧（`RawWaveFrame`）是采集层检查完整性后形成的内部容器；“原始数据访问点”是商用网分数据处理链中的查询阶段。二者不能混用。

### 4.3 从目录移除不等于物理回收

校准数据集“从可选目录移除”只阻止以后新选用，已有合法精确引用仍可继续工作。

“物理回收”才销毁某一修订，并且必须先证明没有仍需保留的引用。公开目录协议见 [D4E §9.1.4 校准数据集的目录移除](./详细设计/04E-产品对象删除与后台处理.md#914-校准数据集的目录移除)，内部回收协议见 [D4D §9.5.4 反向引用、发布记录与物理回收](./详细设计/04D-持久化结果与恢复.md#954-反向引用发布记录与物理回收)。

### 4.4 当前结果不等于历史结果

连续测量通常只需用有界内存中的最新结果刷新迹线；用户明确保存、产品策略要求保留或校准工作流要求留证时，结果才进入持久历史。两条路径都必须保留完整数值含义和来源记录。

### 4.5 自由运行不是触发信号

命令触发、外部边沿和外部电平可以有明确的输入来源；自由运行是内部调度策略，不进入外部触发输入组合。它们先形成测量推进候选，只有通过完整准入提交后才形成 `AdvanceEvent`；因此不应统称为“四种触发信号”。

前面板“手动触发”是一次命令触发；单次（Single）、启动（Initiate）、运行保持（Hold）是运行模式或控制动作，不能因为都由人点击就混成手动触发。迹线最大/最小保持是另一类数值处理状态，不属于本段的运行控制动作。

## 5. 项目路线与验收术语

| 名称 | 白话含义 |
| --- | --- |
| P0 | 阻止进入生产或发布的最高优先级缺陷；只有精确环境中的有效通过记录才能关闭 |
| R0–R2 | 现有三层的整改阶段：先隔离验证路径，再关闭设备/数值和运行责任缺陷 |
| S1–S7 | 按用户可观察能力递增的产品纵向切片，不是按软件层编号开发 |
| S11-WS | 受限的 S11 纵向验证骨架；只验证层间接缝，不能安装、不能当作产品能力 |
| 验收门（内部标识常含 `Gate`） | 一类必须证明已经满足、否则阻止相应切片进入生产或发布的条件 |
| 验收范围（Scope） | 把一组断言、定义版本、环境和证据边界固定在一起的可签发评估单位 |
| ScopeRegistry | 验收范围的版本化登记表；当前 19 项全是“待评审候选定义”（内部标识 `DraftPendingReview`），正式发布和有效通过记录都为 0 |
| 厂商兼容配置（`Profile`） | 绑定精确型号、固件、选件、连接方式和协议映射的兼容配置；一份配置的证据不能替另一份配置通过 |
| 候选定义自洽 | 文档结构和定义哈希能够复算；只说明定义没有自相矛盾，不表示验收门、P0、阶段或厂商兼容已经通过 |

## 6. 证据边界

- ZNB、ZNBT、SNA 手册和实机记录用于确认可观察的产品行为与术语。
- SNA 逆向观察只证明登记过的二进制边界和静态依赖。
- 固定版本开源代码只提供算法、缓冲、错误处理和测试机制参考。
- VnaPro 的分层、对象和恢复协议是本项目设计；除非有一手证据，不写成厂商内部事实。

遇到同义词或新缩写时，先更新本页，再在正文使用；不要在单篇文档中另造第二套名称。
