# 网络测量层原型说明

## 当前交付

本原型实现《网络测量层软件设计》v0.3 中属于 `VnaMeasurement` 自身的 V1 同步范围：

- `compileMeasurement()` 从同一份 `ObservationDefinition` 推导直接波依赖，按
  `(WaveKind, PortId)` 去重排序并注入扫描骨架；
- `bindMeasurement()` 逐字段绑定权威 `PreparedAcquisition`，重建稀疏激励的共享点索引和输出偏移；
- `buildObservationFrame()` 把一份 `RawSweepFrame` 确定性转换为一份不可变
  `ObservationFrame`；
- 支持直接波与同一激励出现内的复数比值，分别保存分子、分母输入质量和本层计算质量；
- 编译、绑定和逐帧构造均执行 checked 容量门禁，失败不发布半成品；
- 公开结果对象禁值复制和移动，通过 `shared_ptr<const ...>` 共享代次；旧帧始终由自身持有的
  `PreparedMeasurement` 解释。

生产目标名为 `VnaMeasurement`，公共入口是
[`modules/VnaMeasurement/include/VnaMeasurement.h`](../modules/VnaMeasurement/include/VnaMeasurement.h)。

## 分层边界

本模块只提供三个无状态同步入口，不持有 `IVnaHardware`，不订阅 Acquisition 事件，也不建立第二套
Prepare/Start/Stop/Abort 状态机。调用链保持：

```text
未来 Channel / 校准 / 协调层
    -> VnaMeasurement
    -> VnaAcquisition
    -> VnaHardware
```

设计 §8 的 `PreparedEventSlot`、provisional `RunIngress`、有界 `FrameWork` mailbox、Worker 和 Run
完成屏障明确属于未来上层协调器。当前仓库没有该上层，因此本次实现不能据同步函数和测试 Harness
声称“生产有界协调器”已经交付。把这些状态塞入 `VnaMeasurement` 会破坏设计规定的单向依赖和同步
边界，故保持为后续独立实现项。

## 使用顺序

调用方应保留自己的产品配置作为重建请求的事实源，并遵守以下顺序：

1. 用空 `requiredWaves` 的已展开扫描骨架和观测定义调用
   `compileMeasurement(std::move(request), limits)`；
2. 把返回的 `MeasurementCompilation::sweepPlan` 移动提交给 Acquisition Prepare；
3. Prepare 成功后，用同一 compilation 的 `compiled` 和回调携带的
   `PreparedAcquisition` 调用 `bindMeasurement()`；
4. 只有 bind 成功后才允许 Start；
5. 对每份 Raw Frame 使用其对应代次的 `PreparedMeasurement` 调用
   `buildObservationFrame()`。

Acquisition 事件允许早于 `prepareAsync()` 或 `start()` 返回，`onSweepReady()` 返回形成 Sweep 级
反压，成功帧先于同 Run 终态，每个已接纳 Run 恰有一个终态。这四条语义现已进入
`VnaAcquisition.h` 公共契约。未来协调器必须在提交调用前建立 provisional 上下文，不能依赖“方法
先返回、回调后到达”的时序假设。

## 数值与质量语义

直接波只在输入带 `Missing` 或复数分量非有限时规范化为 `{quiet_NaN, quiet_NaN}`。比值分别判断
两个输入是否可用，并可组合记录：

- `InputUnavailable`；
- `ValueNonFinite`；
- `DenominatorNonFinite`；
- `DenominatorZero`；
- `ResultNonFinite`。

`Overload`、`Unlocked`、`SourceUnsettled` 和 `ReferenceLow` 不会单独阻断有限计算，其原始位仍分别
保存在 numerator/denominator quality 中。Missing 操作数的占位零或 NaN 不会额外制造零分母或非
有限事实。本层不引入近零 epsilon，也不把未经校准的 `b/a` 自动命名为最终 S 参数。

## 容量门禁

两项 `MeasurementLimits` 都必须非零：

- `maximumPreparedPayloadBytes` 限制扁平编译签名、观测定义、依赖、绑定描述符和共享点索引；
- `maximumBuildPayloadBytes` 限制一份 Observation values/status 和每个不同输入波一项的临时 View
  表。
- compile 在任何按输入规模建立去重集合或依赖 vector 前，先以 `P/X/S/O` 计算最小 payload 并拒绝
  超预算请求；精确 `E/D/T` 在受限集合内完成后仍复用同一 payload helper。

compile 与 bind 调用同一个 payload helper。预算按标准布局内部类型的逻辑 `count * sizeof(type)`
计算，不包含 vector 对象、capacity 余量、allocator 元数据、shared_ptr 控制块、下层
`PreparedAcquisition` 或进程 RSS。

4 端口、10,000 点、4 激励、每激励 5 个直接波、每激励 4 个 Ratio 的参数化用例验证：

- Raw 有效样本载荷为 `4,000,000 B`；当前 64 位 Acquisition 组帧预算为 `4,000,032 B`；
- Observation values/status 载荷为 `4,480,000 B`；
- `D=20` 的 build scratch 另计 `20 * sizeof(RawWaveSeriesView)`；
- Acquisition 精确预算通过，少 1 B 返回 `UnsupportedPlan`；完整 bind/build 产生 160,000 个观测样本。

## 构建与验证

```bash
cmake -S . -B build/measurement-test -G Ninja \
  -DCMAKE_BUILD_TYPE=Debug \
  -DVNA_BUILD_TESTS=ON \
  -DVNA_BUILD_BENCHMARKS=OFF
cmake --build build/measurement-test --parallel
ctest --test-dir build/measurement-test --output-on-failure
```

聚焦测试覆盖编译规则、逐字段绑定、容量 exact/−1、稀疏乱序 ID、Direct/Ratio 质量真值表、旧代次
生命周期，以及通过 Fake Hardware 的
`compile -> prepare -> bind -> start -> Raw -> build` 完整链路。

当前 Debug 全量结果为 126/126 通过。专属 Release 基准使用固定的 4P/10k/4 激励/每激励 5 波/16
Ratio 形状，setup 真实经过 compile、Acquisition prepare、bind 和 Raw freeze，计时区间仅包含
`buildObservationFrame()`：

```bash
cmake -S . -B build/measurement-benchmark \
  -DCMAKE_BUILD_TYPE=Release \
  -DVNA_BUILD_TESTS=OFF \
  -DVNA_BUILD_BENCHMARKS=ON
cmake --build build/measurement-benchmark --target VnaMeasurementBenchmark --parallel
build/measurement-benchmark/benchmarks/VnaMeasurementBenchmark
```

本机一次 20 帧预热、200 帧采样得到 P50 2.329 ms、P95 2.438 ms、P99 2.686 ms；该数字只用于确认
基准可重复执行，不是跨机器性能门禁，也不代表端到端队列、CPU 或 RSS 指标。

生产工具链继续使用 GCC 7.3.0、C++17 且不构建 GoogleTest：

```bash
docker run --rm --platform linux/amd64 --cpus 1 \
  -v "$PWD":/src:ro -w /src \
  vna-gcc73-toolchain:7.3.0 sh -lc \
  'cmake -S /src -B /tmp/vnapro-production -G "Unix Makefiles" \
    -DCMAKE_BUILD_TYPE=Release \
    -DVNA_BUILD_TESTS=OFF \
    -DVNA_BUILD_BENCHMARKS=OFF \
    -DVNA_ENFORCE_PRODUCTION_TOOLCHAIN=ON && \
   cmake --build /tmp/vnapro-production --parallel 1'
```

当前实现已通过上述 Linux/amd64、GCC 7.3.0 串行全量生产构建；七个 `VnaMeasurement` 翻译单元还
单独通过了 `-Wall -Wextra -Wpedantic -Werror -fsyntax-only`。arm64 主机上的 QEMU 首次全量构建曾在
未改动的 Hardware 翻译单元触发 `cc1plus` 内部崩溃，保留构建目录重试后全量完成；该工具崩溃不被
当作源码通过证据，也没有放宽任何编译诊断。

## 尚未关闭的门禁

- 上层有界协调器及其早到事件、预留终态槽、首错锁存、Stop 和完成 fence 竞态尚未实现；
- 真机波值单位、参考阻抗、参考平面、工厂归一化和跨设备物理一致性仍未关闭；
- build-only 手工基准只能建立本层数学转换基线，端到端 Continuous 的队列等待、慢消费者反压、
  CPU、RSS、分配计数和完成 fence 阈值仍需随未来协调器实测冻结；
- Simulator 只能验证映射和复数数学，不能替代真机校准与最终 S 参数正确性验证。
