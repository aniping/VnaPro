# 现有三层审计 02：VnaAcquisition

> [返回审计入口](../现有三层架构审计与整改方案.md) · 上一篇：[VnaHardware 审计](./01-VnaHardware审计.md) · 下一篇：[VnaMeasurement 审计](./03-VnaMeasurement审计.md)

本篇只记录当前代码证据、风险、目标去向和验收结果。运行状态与触发竞态由 [D3](../详细设计/03-运行时触发与调度.md)维护，结果提交与恢复由 [D4D](../详细设计/04D-持久化结果与恢复.md)维护，全局验证门禁由 [D5](../详细设计/05-适配器横切与验证.md)维护。

## 1. 结论

组帧和单次物理执行能力可以迁移，但 Finite/Continuous、下一 Sweep 和产品级 Run 必须上移 L6。L3 只负责一次设备执行的数据接入、完整性检查和采集终态。

## 2. 保留

- `PreparedAcquisition` 预编译扁平映射，热路径不重复解析嵌套计划。
- `RawFrameAssembly` 区分缺块与样本质量；只有完整覆盖才冻结不可变 Frame。
- 容量计算采用 checked accumulate/乘法，Prepared 和单帧 payload 有显式门限。
- Stop/Abort、首错和唯一 acquisition terminal 已有细致竞态测试资产。

## 3. 问题

### P0

以下是四个中央 P0 中“通道测量任务责任重复”在 Acquisition 的层内证据，不是新增第五个中央 P0。

- Acquisition 自己拥有 Finite/Continuous 和下一 Sweep 提交。
  - 风险：与 Runtime/Scheduler 同时改写通道测量任务；详见[跨层 P0 1.4](./04-跨层P0问题.md#14-通道测量任务责任重复)。

### P1

- `VnaAcquisition.h:172-174` 接收共享 `IVnaHardware`。
  - 风险：外部仍能并发发送硬件命令。
- `VnaAcquisitionEngine.cpp:79-86` 中，活动操作析构只打印，不 Stop/Drain。
  - 风险：退订后硬件仍运行，或终态消失。
- `VnaAcquisition.h:142-150` 明文允许回调早于 API 返回。
  - 风险：上层必须维护临时映射，竞态会逐层放大。
- `VnaAcquisitionEngine.cpp:128-135` 对 `onSweepReady` 异常只记录。
  - 风险：数据没有被消费，Run 却可能继续 Completed。
- `RawSweepFrame` 是可无限保留的 shared_ptr，Limits 只有单帧和 Prepared 上限。
  - 风险：慢消费者长期保留会使 RSS 无界增长。
- Frame 只含 run/sweep/index，Point 输出只是 ordinal。
  - 风险：无法追溯分段、量化、流水线和数值含义。
- 完整帧生成后复制 values/quality，上层又分配 Observation。
  - 风险：高点数、多端口时峰值内存倍增。

### P2

- 局部分配失败有时映射为 InternalError。
  - 风险：资源耗尽与内部错误无法一致诊断。

## 4. 整改目标

1. Acquisition 收缩为一次物理执行，不再自行提交下一次扫描。S11-WS 只让 L6 管理一次 Single；Continuous 由 S2 在同一边界上扩展。
2. L3 只消费独占执行能力，其他组件不能绕过它并发控制同一硬件执行。
3. 活动采集提供有截止时间的显式关闭；析构只做最后的错误保护。
4. 数据消费者明确确认接收或拒绝；拒绝必须进入本次采集的首错和终态。
5. 已发布 Frame 继续占用自己的有界额度；慢消费者不能让进程内存无限增长。
6. L3 Frame 只记录物理采集来源和数值 Schema。已接纳的测量推进事件、目标批次和产品绑定属于 L6 信封与最终结果来源，不写回 L3。
7. 先用全链资源账证明上限，再用基准决定是否引入共享列或 arena；零复制不是先决条件。
8. 容量不足统一报告资源耗尽，并指出发生在哪个组件或字段。

字段和物理组帧合同见 [D1：公共契约、驱动、硬件与采集](../详细设计/01-公共契约与硬件采集.md)；运行父子关系、触发、停止和结果完成见 [D3：运行时、触发与调度](../详细设计/03-运行时触发与调度.md)；结果持久化见 [D4D](../详细设计/04D-持久化结果与恢复.md)；资源账和全局竞态验收见 [D5](../详细设计/05-适配器横切与验证.md)。

## 5. 验收

| 验收域 | 必测场景 | 通过结果 | 权威详设 |
| --- | --- | --- | --- |
| 数据完整性 | 缺块、重复、乱序和坏质量 | 不完整数据不发布；坏质量按声明规则传播 | [D1](../详细设计/01-公共契约与硬件采集.md) |
| R2 容量与背压 | 反复 Single、慢消费者、上下游重叠 | 单目标的 RSS 和在途数量稳定在上限；容量不足在建立运行前明确拒绝 | [D3](../详细设计/03-运行时触发与调度.md)、[D5](../详细设计/05-适配器横切与验证.md) |
| 生命周期边界 | 等待测量推进、执行中和排空时停止或关闭 | L3 不启动下一扫描；设备槽释放与结果完成各有唯一结论 | [D3](../详细设计/03-运行时触发与调度.md) |
| 公共链 | Simulator 经真实插件边界进入 Hardware、Acquisition、Runtime 和数值链 | 不以层内 Fake 替代公共边界，结果与来源正确 | [D5](../详细设计/05-适配器横切与验证.md) |
| R2 稳定性 | 长时重复 Single、TSan、ASan/UBSan | 无无界增长、数据竞争、泄漏或悬空回调 | [D5](../详细设计/05-适配器横切与验证.md) |

24 小时 Continuous 属于 S2；多目标整批准入、逐目标准入和分组触发属于 S5。它们的长时、容量和并发验收不得用 R2 的单通道 Single 证据代替，也不应在 R2 预先实现。
