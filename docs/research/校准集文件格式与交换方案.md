# 校准集文件格式与交换方案

日期：2026-10-16。最终范围以用户最新决定为准：效率优先，默认 VnaPro 自有 `.vcal`，另提供 CSV；不支持 Snau 文件或旧 JSON 文件，不自动迁移旧池。此前厂商研究保留为证据，不作为产品兼容声明。

## 保存与交换

每集为不可变、自包含 `.vcal`，保存完整身份、方法、端口、频轴、逐点功率、IFBW、隔离状态、名称及全部系数。小型 `channel-1.json` manifest version 2 只负责原子事务索引与选择，不保存系数数组。版本 1 及单集 JSON 被明确拒绝，原文件保留。新池不生成 `compact-cache`。

启动先读取二进制并校验完整性，随后服务全量验证数学、设备和刺激约束并深冻结，存储层核对后共享冻结对象，全部完成才监听。首次 ACT 不读取、解码或重建系数。仅更换格式不能消除数学验证成本，完整启动及 ACT 必须用相同合法池配对测量，不能把单文件 codec 微基准当整库成绩。

导入统一进入已有服务校验、资源预算与保存屏障，分配新 ID，不自动替换当前选择或启用校正。当前设备身份仍不足以区分同型号板卡，使用者须确认实际仪器和连接路径；新格式不会补造设备序列号。

## `.vcal` 线格式 v2

全部整数为无符号、小端；浮点为 IEEE 754 binary64，小端逐位写入，不直接转储 C++ 对象。文件上限 8 MiB。

| 头偏移 | 字段 | 字节 |
| --- | --- | --- |
| 0 | ASCII `VNBCAL02` | 8 |
| 8 | version，固定 2 | 4 |
| 12 | flags，固定 0 | 4 |
| 16 | payloadBytes，须与实际文件长度一致 | 8 |
| 24 | payload 的 FNV-1a 64 校验值 | 8 |

载荷固定头为 48 字节，随后是可变内容：

| 载荷偏移 | 字段 | 字节 |
| --- | --- | --- |
| 0 | source ID | 8 |
| 8 | method：1/2/4 | 4 |
| 12 | includeIsolation：0/1 | 4 |
| 16 / 20 | port1 / port2 | 各 4 |
| 24 | points | 4 |
| 28 / 32 | nameBytes / deviceIdentityBytes | 各 4 |
| 36 | reserved，固定 0 | 4 |
| 40 | IFBW，Hz | 8 |
| 48 | UTF-8 name、deviceIdentity，无末尾 NUL | 按长度 |
| 其后 | 全 frequencyHz、全 powerDbm、全系数 | 每数 8 |

source ID 为 1～18446744073709551614，0 与 uint64 最大值保留；导入后仍分配新 ID。name 最多 128 字节，身份为 1～512 字节；点数 2～10001。单端口 port2=0，双端口为两个不同物理口，四端口固定 port1=1、port2=4。每个复数均为实部/虚部。

单口每点 6 个系数 double，双口 24 个，四口 96 个；加完整频轴和功率，每点分别为 64/208/784 字节。双口顺序为 `Df,Sf,Rf,Xr,Lr,Fr,Xf,Lf,Ff,Dr,Sr,Rr`。四口按接收行、激励列 S11、S12、…、S44，每格 offset/match/tracking。对角是 D/S/R，非对角是 X/L/F；未采隔离时非对角 offset 为零，不表示额外求解了隔离。

拒绝错误魔数/版本/flags、长度/形状不符、尾部数据、非法 UTF-8、非有限数及校验失败。服务继续验证严格递增整数 Hz、实际刺激兼容、跟踪项及校正结果有效性。FNV 的初值为 14695981039346656037、乘数为 1099511628211，按 uint64 溢出；它只检测意外损坏，不提供来源认证。

## 完整 CSV v1

默认带 UTF-8 BOM、CRLF；导入也接受无 BOM 和 LF。首行为 `vnapro_calibration_csv,1`，之后依次为以下两列元数据行：

```text
source_id,text:<十进制 uint64>
name,text:<名称>
device_identity,text:<设备身份>
method,onePort|twoPort|fourPort
port1,<物理口>
port2,<物理口或0>
include_isolation,true|false
if_bandwidth_hz,<Hz>
points,<点数>
```

下一行为固定列头：`frequency_hz,power_dbm`，再按相同物理接收行、激励列展开每项实部/虚部，例如 `S11_directivity_real`、`S11_directivity_imag`、`S12_isolation_real`。共 8/26/98 列，每频点一行。非连续双口如 P4/P2 保留该物理方向和顺序。

数字使用点号、17 位有效数字，保留原样导出导入的 binary64 和负零。文本按 CSV 引号规则转义，固定 `text:` 前缀避免公式执行或长 ID 精度损失；不得删掉前缀。仅有 freq/“误差”两列不足以恢复可用校准集：这里保存的是方向明确的校准误差系数，不是校正后残余误差或仪器精度指标。

缺元数据、重复/乱序/多余列、少行、多行、非有限数、逗号小数、非法引号和超过 32 MiB 都拒绝。表格软件另存可能改变精度，不将编辑后的 CSV 承诺为无损备份。

## HTTP 文件封套

`GET /api/v1/calibration/sets/{id}` 默认 binary，可指定 `format=binary|csv`，并可与 `channelId` 同用。返回 format、encoding、filename、byteLength、content；binary encoding 为 base64，csv 为 utf8。下载文件不是 JSON。

`POST /api/v1/calibration` 使用 `action:importFile`、format、encoding、content 及原 requestId/expectedRevision/控制租约。旧 `action:import` 明确拒绝。原始 CSV 限 32 MiB，HTTP 封套、输出及规范重试指纹限 36 MiB，为固定最大行列的引号/换行转义预留空间；普通控制请求仍限 16 KiB。Base64 检查长度、padding 和末尾无效位后才解码。权限、幂等、版本冲突、异步操作及实际保存屏障沿用现有协议。
