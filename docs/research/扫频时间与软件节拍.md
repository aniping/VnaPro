# 扫频时间与软件节拍

核对日期：2026-10-17。参照型号为用户确认的 R&S ZNB；另按用户要求只读核对仓库内固定版本思仪 Snau。没有启动原厂程序或操作运行中的 VNB。

## R&S ZNB 的公开合同

来源为 [ZNB User Manual v74 / FW V4.25](https://scdn.rohde-schwarz.com/ur/pws/dl_downloads/pdm/cl_manuals/user_manual/1173_9163_01/ZNB_UserManual_en_74.pdf)，SHA-256 `874901ee4e880dbca9a606406df448494f610233f0cd3b6a61244464b19fdccd`，与 `docs/reference/znb8/source-manifest.json` 一致。以下为 PDF 页码。

| 项目 | 已证事实 |
| --- | --- |
| Sweep Time / Auto | p535：Sweep Time 是整扫的总测量时间；Auto 采用当前参数允许的最短时间并把 Meas Delay 归零。增加扫时会在部分测量前增加延迟，不能解释为扫完后的界面暂停。 |
| 最短值 | p541、1476：与点数、IFBW、部分测量数及测量前延迟有关，没有通用固定最短值。 |
| 命令 | p1475–1476：`SENS1:SWE:TIME <秒>`、`SENS1:SWE:TIME?`、`SENS1:SWE:TIME:AUTO ON/OFF`、`SENS1:SWE:TIME:AUTO?`；写 TIME 关闭 Auto，Auto 复位为 ON。普通频率扫上限为 100000 秒。p1476 有一处示例把写 TIME 后的 AUTO 查询写成 1，与同页明确正文冲突，本项目不采用该例子。 |
| 单位 | p877–878 的通用单位规则支持秒及 milli/micro/nano 前缀，如 `500 MS`。 |
| 不可泛化的模式 | p535–536、549、1451–1452：Swept 与 Stepped 不同；Swept 下 Sweep Time 禁用；段扫有独立段时间，单段上限 1000 秒。当前线性频率扫实现不能宣称覆盖这些模式。 |
| 慢扫箭头 | p814：扫时超过某上限才显示向下指向迹线的箭头；没有公开数值阈值、滞回、帧率或精确外形。快速扫描无需显示瞬移箭头。 |

ZNB 的最短扫时估计依赖原厂硬件；本项目不能把一次主机回读耗时称作同等精度的硬件估计。扫时改变也不等于频率插值。[ZNB 规格 v08.00，p10](https://cdn.rohde-schwarz.com.cn/pws/dl_downloads/pdm/cl_brochures_and_datasheets/specifications/3608_3278_22/ZNB_specs_en_3608-3278-22_v0800.pdf#page=10) 的不确定度条件包含测量与校准采用相同扫时；它不能单独证明“修改扫时必须 Cal Off”。

## 固定 Snau 的实际数据流

固定目标为 `reference/analysis/sna/targets/Snau.exe`，SHA-256 `69fcbde60ef7102074c7adadc86610a9b6921e222e588edde1a40de05a224bc1`。它是原生 x64 PE，没有 .NET CLR；以下为映像基址 `0x140000000` 下的原生虚拟地址，不是 IL 地址。通过既有 Ghidra 12.1.4 工程以 `-readOnly -noanalysis` 导出，未执行原厂程序。

| 环节 | 地址与直接证据 |
| --- | --- |
| 设置与最短时间 | `0x14040C1C0` 的对话框处理调用 `0x1404B2990`；后者比较请求时间与 `0x1405B3330 → 0x140551920` 算出的自然时间，选择手动/Auto，并由 `0x1404B0DB0` 保存。`0x1404AF7F0` 同样耦合 Auto 与自然最短值。属性 `0x15` 是扫时，`0x16` 是 Auto。 |
| 通道同步 | `0x1405AF1E0` 在 `0x1405B0281` 调用 `0x1404AF7F0`，随后调用已命名的 `CLsbChannel::SetSweepTime`；不是只修改 UI 文本。 |
| 每点时间描述 | `0x14054FF40`、`0x1405503B0` 从 `CLsbChannel::GetSweepTime` 取秒值，按 `max(0, trunc((总扫时/点数 − 当前IFBW自然点时)/1.2µs))` 得到附加时间数量，写扫描描述块 `+0x70`。常数 `0x140677E88` 的原始 double 为 `1.2e-6`，文件偏移 `0x676C88`。自然点时函数为 `0x140552BF0`，依赖 IFBW 和设备参数，不能简化为单一 `1/IFBW`。 |
| 真实设备消费者 | `0x14055AA40` 把描述块 `+0x70` 拷入待发送包的 `+0x60 / +0xAC / +0xCC`，再调用 `0x140139480`；后者在 `0x1401394E4` 直接调用 `CDspIO::WriteBuff`（IAT `0x14065D1B8`）。因此这条真实 DSP 路径确实下发了时间字段，不能说它只是延后主机回读。DSP 内部如何消费该字段尚未实测。 |
| 软件等待分支 | `0x140559A80` 在全局 `0x14090EA18 != 0` 时，按属性 `0x15 / 点数 × 1000` 算每点毫秒，推进 `CLsbChannel::SetSweepPoint`；不足 1 ms 调 `0x140358EA0` 用 QPC 忙等，其余在 `0x140559C61` 调 `Sleep`。这不是上述真实 DSP 分支。 |
| 分支身份 | `0x140136550` 先将该全局置 1；只有打开 DSP、初始化、自检、取得共享内存等均成功后才在 `0x140136A0A` 置 0。`CDspIO::WriteBuff` 包装在该全局非零时直接返回成功、不写 DSP。可证明是没有成功连接 DSP 的软件分支；没有凭空还原其源代码变量名。 |

采集循环中还有常量 `Sleep(1)`、`Sleep(3)` 等让步/等待；没有数据流证明这些常量是手动 Sweep Time 的实现，不能仅搜到 Sleep 就下结论。以上静态证据只针对这个固定版本；不代表其他思仪型号、固件或 VN10 接口具有相同字段。

随包 `Program.pdf`（SHA-256 `a53d5ebcd45ff7714e4eff393cb7130a12867950049cdd114202fe689fafa878`，PDF p515–517 / 印刷 p505–507）描述 `SENS:SWE:TIME`、`TIME:AUTO`，但其不同型号上限不能替代 ZNB 上限。归档与来源见 [随安装包厂商手册及校准文件核对](../../reference/analysis/sna/vendor-manuals.md)。

随包 3671 `Guide.pdf`（SHA-256 `69391dce00d626e20b742700ebc0c95c912d85e241ce2bd902131edd3cdb3e2f`，PDF p106 / 印刷 p103）另明确：扫时为 0 选最快，至少 300 ms 才显示指向刚完成测量点的向上小箭头。这是思仪型号合同，不能据此把 ZNB 的向下箭头或未知阈值改写为 300 ms。

## 本项目的实现边界

用户明确要求在当前硬件没有原生 Sweep Time 入口时采用软件等待。当前绑定的 VN10 九个入口没有 Sweep Time / Dwell 设置，故采用主机侧、每段真实 `DrvGetSweepData` 前的可唤醒节拍；不新增或猜测原生 ABI，不写入尚未验证的 DSP 字段。

- Auto 不增加等待，保留原有最多 64 点回读粒度。手动值为最小完整回读时长；按本扫开始时间和请求前缀比例安排绝对截止时间。真实采集、原生 Get 或调度较慢时允许超过目标，不承诺加速硬件。
- 手动慢扫可缩小每次 Get 点数以约 100 ms 推进，收齐该前缀全部工作源才发布。数据已在硬件中产生但尚未回读的情形仍可能存在；这不是 ADC 驻留控制、DUT 稳定等待或原厂 Chopped 调度。
- Stop 仅匹配通道和 run，Close 可唤醒人工等待。同通道且已经通过核心输入验证、成功入队的 Configure 也可唤醒，以免切回 Auto 仍等待旧手动目标；Service 仍先检查控制权和配置版本。错误参数、未入队请求或其他通道的配置不能取消当前节拍。唤醒后继续排空已经启动的原生扫描，恢复最多 64 点回读；不宣布未完成数据已经完成，原生 Get 本身没有经验证的强制取消能力。
- 修改扫时走现有配置版本与权限检查，并清除旧配置的实测扫时/预览。HTTP/SCPI 完整数据、校正和完成屏障继续使用完整帧；不把播放时长改变成测量完成事件。
- 输入仅接受有限的 `(0,100000]` 秒，写入数值关闭 Auto。当前没有 ZNB 级最短扫时估算；`TIME? MIN` / `TIME? MINIMUM` 明确拒绝，最快节拍应使用 `TIME:AUTO ON`。Auto 普通查询返回当前配置上一完整扫的实际回读秒数，尚无完整扫时返回 0；这个未知值不是可设置的最小时间。UI 分别展示 Auto/目标和 Last Sweep。低于自然完成时长的目标不会提高实际采集速度。
- 1 秒慢扫判断、至少预估剩余 0.5 秒与 100 ms 发布节流均为项目策略，不是 ZNB 公开参数。预览/箭头只随真实回读点推进，完成后清除；未知原厂细节仍见 [ZNB 慢扫局部刷新行为核对](ZNB慢扫局部刷新行为核对.md)。

本轮私有函数导出、汇编、只读 Ghidra 日志与 PE 常数读取位于 `.git/task-review/sweep-time-20261017/`，不提交原厂反编译产物。验收应分别覆盖手动目标、Auto 无额外等待、错误通道/旧 run 的 Stop、Stop/Close 排空、多通道隔离，以及完整帧与配置身份不变。
